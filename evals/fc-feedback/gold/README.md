## 1. 분할 규칙 (§14.6)

새 유닛은 다음 중 하나에서 시작한다.

1. **대상 선수/장면이 바뀌는 주제 전환 발화** — "[닉네임]님 + 아쉬운 거라면/보면은" 같은
   패턴(예: "조민님 아쉬운걸 하면 하나 있네요", "스프레스님 보면은").
2. **15초 이상 무음 뒤 새 지적** — 직전 발화 종료 시각과 다음 발화 시작 시각의 간격이
   15초 이상이고, 이어지는 발화가 새로운 지적(비판/제안)일 때.

잡담과 경기 외 발화(인트로 인사, 점수 확인 잡담, 단순 리액션, 의미를 특정할 수 없는
ASR 파손 구간)는 유닛으로 만들지 않는다. 제외한 줄과 사유는 §4에 정리했다.

## 7. 재생성 검증 (사용자 확인 2026-09-28, roster 확장에 따른 `lines.json` 재생성)

roster.cef.yaml의 alias가 바뀌면 `fc.ts transcribe`의 alias 정규화 결과도 바뀌므로,
`work-NUzEChn9EyI/lines.json`을 실제로 재생성해 확인했다(evals 메인 `README.md`

다시 실행했다). 결과: 190줄 그대로, 모든 줄의 `i`/`start`/`end`가 기존
`lines.json`과 **완전히 동일**했고, 텍스트만 6곳에서 바뀌었다(전부 §5.1에서 병합한

`lines.json`을 이 재생성 결과로 덮어썼다.

**중간에 찾은 버그와 우회.** 최초 시도에서는 `find` 멤버의 `name`을 최빈 표기
"파인드"로 뒀는데, `media.ts`의 `applyAliases`가 alias를 길이 내림차순으로 순차

alias "사인드"의 치환 결과) 안의 "파인" 부분과 다시 매칭돼 i=40/121/161/124/127의

`name: 사인드`로 바꿔 우회했다(§5.1에 근거 정리). 이 우회를 적용한 뒤 재생성한
