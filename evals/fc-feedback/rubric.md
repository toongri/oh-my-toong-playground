plan §14.3(배점 확정, §13.3보다 우선) + §14.5(심사 계약) + §15-7(reader_persona 고정)을
그대로 옮긴 채점 계약. `score.ts`는 이 문서의 배점만 사용한다 — 배점을 바꾸려면 이 문서를
먼저 고치고 `score.ts`를 맞춘다.

## 자동 채점 60점 (score.ts)

- **check 게이트** — `check plan` / `check notes` / `check similar` / `check refs` 4종 중
  하나라도 exit≠0이면 그 반복의 총점은 0이다(다른 배점을 계산하지 않는다).
- **단위 F1 (25점)** — gold 단위와 산출 단위를 시작 줄 ±15초 오차 안에서 1:1로 매칭한 뒤
  재현율·정밀도의 F1을 25점 만점으로 스케일한다. 매칭은 가능한 쌍의 개수를 최대화하는 것이
  1순위이고, 최대 매칭이 여럿이면 시작 시각 오차 총합이 가장 작은 매칭을 고른다(동률 처리).
- **시작 시각 정확도 (10점)** — 매칭된 쌍들의 시작 시각 오차(초)의 중앙값을 쓴다.
  0초=10점, 오차가 늘수록 선형으로 감점, 20초 이상=0점.
- **태그 F1 (15점 = 포지션 5 + 주제 5 + 팀원 언급 5)** — 매칭된 단위 쌍에서만 포지션/주제/
  언급 팀원 태그 집합의 F1을 각각 계산한다. 포지션 기반으로 결정론적으로 계산되는
  "관련 팀원"은 채점 대상이 아니다 — "언급 팀원"만 채점한다(§14.6).
- **참고자료 10점 (URL 포함 4 + http 상태 3 + 외국어 요약 3)**:
  - URL 포함 판정(4점): `refs-draft.json`의 각 URL이 같은 실행의 `run.jsonl`에서 웹 검색·fetch
    도구 결과(codex `web_search`의 `.item.results[]`, Claude `WebSearch`/`WebFetch`의
    tool_result)에 문자열로 등장하는 비율로 스케일한다. 에이전트 메시지·실행 명령·파일 등
    다른 곳에만 적혀 있는 URL은 인정하지 않는다.
  - http 200–399 비율(3점): `refs.verified.json` 기준, 분모는 (상태코드가 있는 유지된 ref 수
    + verify-refs가 반려해 `dropped`로 옮긴 ref 수)이고 분자는 그중 상태코드가 200–399인
    ref 수다. dropped 항목은 검증에 실패해 반려된 것이므로 분모에서 빠지지 않는다.
  - 외국어 요약(3점): 한국어가 아닌 원문 ref마다 한국어 요약이 존재하는 비율을 3점
    만점으로 스케일한다.
- **규율 위반 감점 (각 −20, 반복 총점 하한 0)**:
  - 초 단위 시간을 직접 기입(계산이 아니라 하드코딩된 것으로 보이는 시각 표기)
  - `git push` 시도(`run.jsonl`의 명령 실행 이벤트에서 검출)
  - 검토 게이트(plan/notes/render 확정) 전에 다음 단계로 진행

## 독립 심사 40점 (presentation-reviewer)

기본 출력(findings + APPROVE/REQUEST_CHANGES)은 점수를 주지 않으므로, 아래 고정 프롬프트로
호출하고 마지막 줄의 `SCORE` 형식을 파싱한다. 형식이 없거나 값이 범위를 벗어나면 그 심사를
재실행한다(재시도해도 안 나오면 해당 반복은 심사 0점으로 기록하고 원인을 회차 기록에 남긴다).

- 문서별 **절대 점수**를 매긴다 — 쌍 비교(A/B)가 아니다.
- 모델 이름은 숨기고 실행 id(run id)만 준다.
- 입력: 렌더된 세션 HTML의 텍스트, `data.json`, `lines.json`, `session.json`(영상
  메타데이터, `files` 필드 제외), 문서에 실린 프레임 이미지, 그리고 문서 작성 에이전트가
  본 전체 후보 미리보기(`cand/`)와 HUD·장면 시트(`sheets/`) — 화면에서 온
  표기(팀명·스코어 등)의 근거 확인용.

### 고정 심사 프롬프트

```
너는 fc-feedback 세션 문서를 평가하는 심사자다. 어느 모델이 이 문서를 만들었는지는
공개되지 않는다 — 아래 run id로만 구분한다: {run_id}

reader_persona: 영상을 아직 안 본 팀원, 모바일에서 읽음. 이 사람의 눈으로 문서를
읽고 판단해라.

입력:
- 렌더된 세션 문서(HTML 텍스트): {rendered_html_text}
- data.json: {data_json}
- lines.json(전사): {lines_json}
- 프레임 이미지: {frame_paths}
- session.json: {session_json}
- 에이전트가 본 후보 프레임·시트: {evidence_paths}

아래 세 항목을 각각 채점해라. 모델명·회차·다른 문서와 비교하지 말고 이 문서 자체를
절대 점수로 매긴다.

1. specificity (0-15): 노트 v2 계약(고정 슬롯 없는 자유 문단 + 두괄식 + 볼드 강조 +
   프레임 캡션)이 실제로 지켜져, 영상을 안 본 팀원이 문단과 사진만으로 상황을 재구성할 수
   있는가. 아래를 모두 본다.
   - 각 유닛의 첫 문단이 핵심 장면을 요약하면서 다음 경기에 시도할 개선 행동을 **볼드**로
     짚는가(두괄식 — 이 문단만 읽어도 무엇을 고쳐야 하는지 알 수 있어야 한다).
   - 이 피드백이 누구를 향한 것인지 문단만 읽고 모호하지 않은가.
   - 뒤따르는 문단과 프레임 이미지가 근거 장면·디테일을 더해, 영상을 안 본 팀원이 문단+
     사진만으로 장면을 재구성할 수 있는가.
   - 볼드가 실제 행동/대상을 짚는 강조로 쓰였는가, 장식적으로 남발되지 않았는가.
   - 프레임 캡션이 그 프레임에 실제로 보이는 것만 서술하는가(시간 경과·상황 변화를 과장
     서술하지 않는가).
   - 팀원 한 명을 골라 30초 안에 "다음 경기에 시도할 행동 1개 + 근거 장면(카드) 1개"를
     말로 지목할 수 있는가(30초 테스트).

   채점 기준:
   - 15: 모든 유닛이 두괄식+볼드 행동을 담고 대상이 명확하며, 문단+프레임만으로 장면이
     재구성된다. 캡션은 보이는 것만 서술하고, 30초 테스트를 여유 있게 통과한다.
   - 10: 대부분의 유닛이 위를 만족하지만 일부 유닛에서 두괄식이 약하거나 볼드가 장식적이거나
     캡션이 프레임 이상을 서술하는 등 사소한 결함이 있다. 30초 테스트는 통과한다.
   - 5: 절반 이상의 유닛에서 대상이 모호하거나 첫 문단이 장면 요약 없이 뭉뚱그린 일반론이고,
     프레임만으로는 장면 재구성이 어렵다. 30초 테스트가 아슬아슬하게만 통과한다.
   - 0: 30초 테스트를 실패한다 — 팀원이 문서를 봐도 다음에 시도할 행동이나 근거 장면을
     지목하지 못한다. 또는 볼드·캡션이 사실상 없거나 장식뿐이다.
2. fidelity (0-15): lines.json 원문과 대조했을 때 코치의 의도를 그대로 복원했는가.
   원문에 없는 내용을 지어낸 것(환각)이 하나라도 있으면 이 항목은 0에 가깝게 채점한다.
   lines.json에 없는 내용도 {session_json}(영상 제목·채널명 등 메타데이터),
   {frame_paths}, {evidence_paths}(화면 표기: 팀명·스코어·경기 정보)에 보이면 근거가
   있는 것이다 — 근거 없음으로 판정하기 전에 확인한다.
3. readability (0-10): reader_persona 기준으로 읽기 쉬운가 — 목차 구조, 문단 길이,
   모바일 가독성을 본다.

마지막 줄은 반드시 아래 형식이어야 한다(값은 실제 채점값으로 채운다). 이 줄 앞뒤로
다른 텍스트가 있어도 되지만, 마지막 줄은 이 형식이어야 한다:

SCORE specificity=<0-15> fidelity=<0-15> readability=<0-10>
```

## gold 대조 회차와 held-out 회차

- 샘플 영상(gold 있음) 점수는 자동 60 + 심사 40을 회차 평균에 넣는다.
- held-out 영상(같은 채널의 다른 파트, gold 없음)은 심사 40점만 별도로 보고하고 회차
  평균에는 넣지 않는다(과적합 감지용). held-out과 샘플의 심사 점수 차가 σ(§14.4)의
  2배를 넘으면 회차 기록에 보고한다.
