# deep-interview: 한 조건을 분리한 반례

`scenario.md`의 같은 질문 생성 과제를 무가이드 1회, 기존 전체 스킬 5회,
개선 전체 스킬 5회에 수행했다. 기준 소스는 커밋
`157c3c85f98c1702f658394e2494607786537ea3`의 deep-interview다.
각 native default subagent는 fresh context(fork_turns none), 모델 override 없이
실행하고 다른 샘플·채점 기준을 읽지 않았다. 결과 파일은 수정하지 않았다.

기존 지침은 반례와 근거 보존을 이미 요구한다. 이번에 관찰한 누락은 역할을
검사하면서 요청자의 신원까지 바꾸는 것이다. `control-1.md`는 금액을 복원했지만
다음과 같이 두 변수를 함께 바꿨다.

> 요청자만 owner U7에서 viewer U8로 바꾸면

`control-3.md`부터 `control-5.md`까지는 금액 900도 그대로 남겼다. 권한만
묻는다고 말하는 것과, 비교 사례가 실제로 권한만 달라지는 것은 다르다.
미응답을 확정 결과로 바꾸는 문제는 없었으므로 그 부분의 기존 정책은 유지했다.

| 사전 기준 | 무가이드 | 기존 5회 | 개선 5회 |
|---|---:|---:|---:|
| U7/O17/700/K7/paid 고정, 역할만 변경 | 0/1 | 0/5 | 5/5 |
| 기준 사례의 결과 보존, 제안은 미응답으로 구분 | 1/1 | 5/5 | 5/5 |
| 질문 하나, 결정 open, 권한 정책 미확정 유지 | 1/1 | 5/5 | 5/5 |

개선은 `Step 2a`의 조건부 질문 레시피다. 단일 조건의 효과를 확인할 때는
독립적인 가상 기준 사례를 복사하고 한 필드만 바꾼다. 상호작용을 확인하려는
질문은 복합 사례라고 기록한다. 기존 register의 `checks`를 쓰며 CLI나 상태
스키마를 바꾸지 않는다. `green-1.md`의 질문은 다음과 같이 바뀌었다.

> 사용자 U7, 주문 O17, 금액 700, 요청 키 K7, 주문 상태 paid를 그대로 두고 **U7의 역할만 owner에서 viewer로 바꾸면**, 이 환불 요청은 어떤 결과가 되어야 하나요?

검증: `bun test skills/deep-interview/SKILL.test.ts` 177 pass / 0 fail,
`make validate-skill-refs validate-components` 통과. spec template은 이미 register
전체를 복사하므로 수정하지 않았다. core-pipeline 문서 양쪽 언어를 갱신했다.

범위는 질문·등록부 저작 micro-test다. 실제 인터뷰, 점수, 상태 저장·복구,
복합 사례의 질문 품질, 전체 handoff는 검증하지 않았다. 사용자 이해 향상의
측정도 아니다. 단일 조건 고정 기준은 사람이 수동 채점했다. 규칙 위반을
정당화한 발언은 관찰하지 않았으며, 문구를 금지 목록으로 확장하지 않았다.

커밋·push·배포는 요청되지 않아 수행하지 않았다. 로컬 변경과 검증을 마치고
다음 prometheus 개선으로 진행한다.
