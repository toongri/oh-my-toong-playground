- actor: 환불 HTTP endpoint를 curl로 호출하는 인증된 API 클라이언트 U7. 주문 소유자는 유지하면서 owner와 viewer 역할을 비교한다.
- preconditions: QA seeder로 성공 요청 직전 상태의 독립 복사본 A/B를 만든다. 모두 U7이 유료 주문 O17을 소유하고 환불 가능 잔액은 700이며, 요청 금액은 700, 키는 K7이다. 각 복사본에는 K7 처리 기록이나 R9가 없어야 한다. A는 owner, B는 viewer 역할만 설정한다. 인증은 두 경우 모두 유효하다.
- steps: 각 복사본의 사전 상태와 역할을 확인한다. A에서 U7 owner로 endpoint에 금액700·K7 요청을 한 번 보낸다. B에서 U7 viewer로 동일 요청을 한 번 보낸다. 실제 요청 및 HTTP 상태·응답 본문을 보존하고, 각 실행 전후 잔액·provider 환불·ledger debit을 비교한다. A 실행 결과가 B에 유입되지 않도록 한다.
- expected: A는 환불 성공 응답을 반환하고 provider 환불과 ledger debit이 각각 한 번 발생하며 잔액은 0이 된다. B는 권한 거부 응답을 반환하고 기존 환불 반환도 없어야 하며, provider 환불과 ledger debit은 증가하지 않고 잔액은 700으로 유지된다.
- why-needed: 역할 권한만 분리하는 자동화 e2e가 없다. 준비된 viewer U8·금액900·타인 소유 O17·K7 사례는 소유권, 초과 금액, 기존 키 처리까지 얽혀 거부 원인을 역할 검사로 귀속할 수 없다. 준비 시간과 검토 마감은 이 근거 부족을 해소하지 않는다.
- priority: H — 결제 권한 우회와 금전 변경 위험이며 해당 경로의 자동화 검증이 없다.

근거 해석: 위 내용은 실행 계획이며 새 근거는 아직 수집하지 않았다. 기존 owner 성공 근거 R9는 비교의 출발점이다. 독립된 같은 사전 상태에서 역할만 바꾼 A 성공/B 거부와 부작용 부재가 관찰되면, 이 조건에서 역할 차이가 환불 허용 여부를 결정한다는 근거가 된다. HTTP 응답은 API 경계 근거이고 provider·ledger 기록은 부작용 확인을 보강한다. 이는 모든 권한 조합, 초과 금액 거부, 동일 키 재생 동작까지 검증했다는 뜻은 아니다.
