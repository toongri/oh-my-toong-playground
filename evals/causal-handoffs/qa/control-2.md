- actor: 환불 HTTP 엔드포인트를 호출하는 인증된 API 클라이언트 U7. 주문 소유자가 viewer 역할로 환불을 시도하는 상황이며 예정 드라이버는 curl이다.
- preconditions: QA seeder로 기존 성공 요청 직전 상태의 독립 복사본 두 개를 준비한다. 두 복사본 모두 U7이 결제된 O17을 소유하고, 환불 가능 잔액은 700, 요청 금액은 700, 키는 K7이다. 각 복사본의 K7은 미사용이며 R9를 포함한 기존 환불·멱등성 기록이 없다. 인증 주체와 소유권은 같게 유지하고 역할만 대조군 owner, 실험군 viewer로 설정한다.
- steps: 각 복사본의 요청 전 상태와 인증 주체·역할을 확인한다. 대조군에서 U7로 금액 700·K7 환불 요청을 한 번 전송한다. 별도의 실험군에서 역할만 viewer인 U7로 같은 요청을 한 번 전송한다. 각각 실제 HTTP 상태·응답 본문과 요청 전후 잔액, 공급자 환불 및 원장 차감 건수의 변화를 보존한다.
- expected: owner 대조군은 환불 성공 응답, 공급자 환불 1건, 원장 차감 1건, 잔액 0을 보인다. viewer 실험군은 권한 거부 응답이며 기존 환불 성공 응답도 반환하지 않는다. 공급자 환불·원장 차감 증가는 각각 0건이고 잔액은 700이다.
- why-needed: 역할 권한만 분리한 자동화 e2e가 없다. 동료의 U8·금액 900·기존 K7 사례는 비소유권, 잔액 초과, 재요청 처리가 섞여 있어 거부되어도 역할 검사의 효과를 판별할 수 없다. 준비 시간과 리뷰 마감은 이 근거 부족을 해소하지 않는다.
- priority: H — 결제 권한 오류는 무단 환불과 금전 변동을 일으킨다.

근거 해석: 위 관찰은 수집 예정이며 실행 결과가 아니다. 대조군 성공과 역할만 바꾼 실험군의 무변동 거부가 함께 관찰되면 이 입력에서 역할에 따른 허용·거부가 작동함을 뒷받침한다. 거부만으로는 부족하며 대조군도 실패하면 역할 검사에 관한 결론을 내릴 수 없다. 모든 역할·소유권 조합, 잔액 초과 및 재요청 동작 전체까지 검증한 것은 아니다.
