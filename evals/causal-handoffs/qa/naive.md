### 역할에 따른 환불 권한 검증

1. **행위자·경계:** 인증된 API 클라이언트가 curl로 환불 HTTP 엔드포인트를 호출한다. 주문 소유자이면서 owner 역할인 사용자만 환불할 수 있다.
2. **사전 조건:** 시더로 요청 전 상태의 독립 복사본 A와 B를 만든다. 두 복사본 모두 U7이 결제된 주문 O17을 소유하며 환불 가능 잔액은 700이다. 기존 환불과 keyK7 처리 기록은 없다. A의 U7 역할은 owner, B는 viewer로 설정한다.
3. **입력·행동:** 각 복사본에서 U7로 인증해 O17에 amount700, keyK7으로 한 번씩 환불 요청한다. 역할 외의 신원, 소유권, 금액, 키 및 초기 상태는 동일하게 유지한다.
4. **예상 응답:** A는 환불에 성공하고 환불 식별자를 반환한다. B는 권한 부족으로 거절된다. 구체적인 상태 코드와 오류 본문은 API 계약과 대조한다.
5. **예상 부수 효과:** A는 공급자 환불 1건과 원장 차감 1건이 발생하고 잔액은 0이 된다. B는 공급자 환불과 원장 차감이 모두 0건이며 잔액은 700으로 유지된다.
6. **수집할 증거:** 각 복사본의 초기 상태와 인증 역할, 요청·응답, 요청에 연결되는 공급자 기록, 원장 및 잔액 전후를 보관한다. 비동기 처리가 있다면 완료 여부를 확인한 뒤 부수 효과를 판정한다.

**증거 해석:** 위 내용은 실행 계획이며 아직 관찰된 결과가 아니다. 예상대로 관찰되면 유효한 소유자의 동일한 환불 요청에서 역할만 viewer로 바꾸었을 때 거절되고 금전적 부수 효과도 차단됨을 입증한다. 준비된 U8/amount900 사례는 비소유자와 잔액 초과 조건까지 함께 바뀌므로 거절되어도 역할 검사 효과를 구분할 수 없다. 이 시나리오는 비소유자 차단, 초과 금액 차단, 동일 키 재요청 동작까지 검증하지 않는다.
