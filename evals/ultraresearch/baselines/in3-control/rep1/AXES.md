# TS DB 마이그레이션 리서치 축과 워커 배정

## 리서치 목적

Alembic의 `multi-head`처럼 마이그레이션 그래프가 분기되어 배포가 경합하거나 실패하는 문제를 줄이면서, TypeScript 기반 서비스에서 배포와 함께 안전하게 실행할 수 있는 도구와 운영 방식을 찾는다. DB 다운 마이그레이션은 요구사항에서 제외한다.

### 직교성 경계

- W1은 **모델의 의미론**만 판정한다. 도구 이름은 증거의 예시일 뿐 후보 순위를 매기지 않는다.
- W2는 **기능 존재 여부**만 수집한다. 배포 구조와 팀 규칙을 권고하지 않는다.
- W3는 **실행 안전성**만 다룬다. 분기 히스토리의 병합 정책은 W1/W4로 넘긴다.
- W4는 **사람·PR·릴리스 절차**만 다룬다. 라이브러리 기능을 해결책으로 가정하지 않는다.
- W5는 새 사실을 수집하는 워커가 아니라 W1~W4의 핵심 주장을 교차 검증하고 선택 기준에 연결한다.

## 워커 지시서

### W1 — 그래프 의미론

- Alembic의 revision DAG와 비교할 수 있는 최소 충돌 시나리오(두 PR이 같은 부모에서 migration을 생성한 뒤 순차 병합)를 정의한다.
- 각 후보가 이를 단일 순서로 강제, merge migration으로 표현, 자동 정렬, 또는 수동 해결 중 어디에 두는지 공식 문서와 코드로 확인한다.
- "Git처럼 자동 병합"과 "Git 충돌을 조기에 차단/선형화"를 구분해 보고한다.

### W2 — 후보 도구 카탈로그

- 현재 유지보수 중인 TS/Node 후보만 short-list에 넣고, PostgreSQL 우선 기준으로 지원 DB를 확인한다.
- 선언형(schema diff)과 명령형 SQL migration, migration 생성·적용·상태 검사·checksum/drift 기능을 분리해 기록한다.
- 롤백 기능은 참고로만 기록하며 점수에는 반영하지 않는다.

### W3 — 배포 런타임

- EKS/Argo CD 환경을 전제로, 애플리케이션 replica가 migration을 직접 경쟁 실행하지 않는 구조를 우선 조사한다.
- PostgreSQL advisory lock 또는 도구 자체 lock의 범위·해제·timeout과, 배포 실패 시 재시도 가능성을 확인한다.
- 결과는 "pre-deploy Job + 완료 후 app rollout"을 기준안으로 두고, 후보별 실행 명령/컨테이너 요구사항을 비교한다.

### W4 — 협업 통제

- migration이 동시에 쌓이는 PR 흐름에서 CI가 무엇을 검사해야 하는지(단일 head, 중복 timestamp, 순서, checksum, pending migration)를 명세화한다.
- merge migration을 허용할 경우와 rebase/재생성을 요구할 경우의 판단 기준을 작성한다.
- 데이터 파괴 없이 전진만 하는 expand/contract 변경 규칙을 포함한다.

### W5 — 검증·의사결정

- W1~W4의 최고 위험 주장(자동 병합, deploy-time lock, drift detection)을 공식 문서/소스/최소 PoC로 각각 검증한다.
- 유지보수성, PostgreSQL 적합성, 배포 통합, 협업 충돌 회피, 선언형 채택 위험을 기준으로 후보를 평가한다.
- 검증되지 않은 기능은 추천 근거로 쓰지 않고 "미확인"으로 남긴다.

## 실행 순서와 의존성

1. Wave 1: W1, W2, W3, W4를 병렬로 실행한다.
2. Barrier: W1~W4의 후보와 주장 목록을 합친다.
3. Wave 2: W5가 핵심 주장과 상충점을 검증한다. 필요하면 W1~W4의 미확인 리드를 후속 워커에 재배정한다.
4. 최종 산출물은 "도구 추천"과 "도구와 무관하게 반드시 도입할 배포·협업 규칙"을 분리해 제시한다.

## 심층 브라우징 워커 결정

**NO — 1차 리서치에는 blocked/auth-gated/JS-rendered 소스 전담 워커를 배정하지 않는다.**

판단 근거는 필요한 1차 증거가 각 도구의 공식 문서, 공개 GitHub 저장소, 공개 릴리스 노트와 이슈에 있어 일반 웹 탐색으로 확보 가능하다는 점이다. 유료 벤더의 로그인 전용 문서, 사내 사용 사례, JS 전용 대시보드는 이번 질문의 필수 증거가 아니다. 공개 문서만으로 `lock`, `drift`, `branch/head`, 실행 명령의 의미를 확인할 수 없는 특정 후보가 생길 때에만 해당 후보 한정으로 심층 브라우징을 추가한다.

## 완료 조건

- 모든 후보 주장은 W2의 기능 표와 W1의 충돌 시나리오에 함께 매핑된다.
- 권장안은 W3의 단일 실행/락 설계를 통과해야 한다.
- 추천 도구가 자동 병합을 제공한다고 주장하려면 W5의 공식 근거 또는 PoC가 있어야 한다.
- "롤백 부재"는 기각 사유가 아니다.
