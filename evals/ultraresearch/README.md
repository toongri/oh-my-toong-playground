# ultraresearch 측정 기록

`skills/ultraresearch/SKILL.md`의 리포트 품질 계약(HTML 고표현력 렌더링, 후보 프로필
필수 필드, 커버리지 워커 귀속, 깊이 링크, 실무자 사례 슬롯)은 전부 여기 있는 측정에서
나왔다. PR 본문이나 테스트 주석에 적힌 "SVG 5/5", "20회 전수 탈락" 같은 숫자를
확인하려면 이 디렉터리를 보면 된다.

이 트리는 **배포되지 않는다**. `sync.yaml`이 참조하는 컴포넌트 카테고리 어디에도
속하지 않는다. 런타임에 필요한 건 계약 문안 자체이고 그건 스킬 안에 있다.

## 왜 저장하는가

baseline 출력은 **다시 만들 수 없다.** 같은 프롬프트를 같은 모델(codex
gpt-5.6-terra, effort high)에 다시 넣어도 같은 출력이 나오지 않으므로, 이 파일들이
사라지면 계약 문안의 모든 수치 근거는 검증 불가능한 주장이 된다.

## 구조

```
harness/
  run.sh               HTML 렌더 시나리오 러너: run.sh <arm> <rep>
  run2.sh              범용 러너: run2.sh <시나리오dir> <arm> <rep> <출력파일명>
  in/  … in6/          시나리오별 픽스처(저널 발췌·기존 계약 문안·프롬프트 3종) — 원본 그대로
baselines/
  <arm>/rep1-5/        전달물만 보존 (stdout·stderr 로그와 입력 사본은 제외)
```

## 식별값 가명 처리

이 레포는 public이다. 픽스처의 저널 발췌(`wave-*.md`)와 baseline 출력에는 실측 당시
조사 대상이던 **사내 private 레포의 이름·경로·리비전·파일명**이 인용 증거로 들어 있었다.
전량 가명으로 치환했다 — 조직/제품명은 `Acme` 계열, 레포는 `acme-home`·`acme-backend`,
로컬 절대경로는 `<repo-root>`, 리비전과 마이그레이션 파일명은 자리표시자.

치환 대상은 **식별값뿐**이다. 측정 수치(리비전 개수·머지 개수·필드 생존 수), 공개
패키지명, 버전은 건드리지 않았으므로 위 표의 모든 주장은 그대로 검증된다. 문서 구조도
보존됐다 — 치환 전후 앵커·링크 수가 파일 단위로 동일하다(`href="#…"` 50, `id="…"` 152,
markdown 링크 658).

**앞으로도 private 출처의 식별값은 이 트리에 들어오지 않는다.** 측정 픽스처는 public
출처에서 고르고, 불가피하게 private 산출물을 보존해야 하면 커밋 전에 같은 방식으로
가명화한다.

`green` = 편집 후 새 계약 문안. 각 arm 5회 반복.

## 실전 A/B (하네스 밖 검증)

TypeScript DB 마이그레이션 라이브러리 질의로 동일 조건 2회 실행 (편집 전/후 스킬,
같은 모델). 세션 산출물은 커밋하지 않으므로 결과만 요약한다.

- 편집 전: HTML이 MD의 0.76배 크기, 인용 링크 11→5 생존, 후보 4종을 한 행에 뭉쳐
  저널 사실 반전(Knex 내장 lock → "외부 lock 필요"), operational governance 축이
  워커 0명인데 `covered` 통과.
- 편집 후: 링크 패리티 30/30, 텍스트 플로우→SVG 승격, 후보 7종 전원 필수
  필드+개별 판정(node-pg-migrate 신규 발굴), 커버리지 표에 축별 담당 조사자 열.
- 잔여 결함 1건이 `in6` 슬롯의 근거: 같은 실행에서 계약 슬롯이 있던 후보 필드는
  전원 생존했는데, 슬롯이 없던 실무자 사례(DoorDash migration manifest 관행)만
  저널까지 오고도 리포트에서 탈락했다. 격리 마이크로테스트로는 이 컨텍스트 압력
  실패가 재현되지 않는다 — 실전 런이 유일한 검증 지점이다.

## 특이 기록

- `baselines/control/rep5/DESIGN.md`: 해당 rep이 REPORT.html 외에 자발적으로 만든
  부산물. 출력 그대로 보존.
- `baselines/in4-new/`·`in4-new2/`의 `REPORT.md`: 이 시나리오는 커버리지 판정이
  리포트 표까지 흘러가는지 보므로 수정된 REPORT.md도 전달물이다 (in4-old는
  REPORT.md를 건드리지 않아 없음).
- 미검증 잔여: 부정결과 피벗, practice 클레임 클래스, intent-diff 종결은 토큰
  테스트만 존재 — 다음 실전 `/ultraresearch` 실행이 행동 검증 지점.
