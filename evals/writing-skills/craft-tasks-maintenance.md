# craft-tasks 출처 무관 입력·재실행 검증

## 변경 목적

craft-tasks가 상위 스킬(deep-interview)의 산출물이나 식별자를 전제하지 않게 한다.
설계는 출처와 무관하게 내용(의도·접근·불변식·경계)으로 판단하고, 분해 대상은 입력으로 받은
이슈 자체다. 재실행 시 중복 방지는 로컬 저널·식별 코멘트 대신 "기존 자식 읽기 → 계획 확인 → 쓰기"로 한다.

## RED 기준선 (실제 세션)

이전 craft-tasks는 `design-anchor: deep-interview:<state.interview_id>` 값을 요구했다.
설계를 대화에서 확정한 세션에서 에이전트는 첫 단계에서 멈췄다. 인터뷰 ID가 없어서 Linear에
아무것도 쓰지 않았고, "직접 생성"과 "deep-interview부터 다시 진행" 중 하나를 고르라고 사용자에게 되물었다.

## GREEN 시나리오

모든 시나리오는 새 `skills/craft-tasks/SKILL.md`와 `presentation.md`만 읽은 서브에이전트가
수행했다. PM 조회 결과는 모의 데이터로 주고, 첫 사용자 입력 지점이나 PM 쓰기 직전에서 멈추게 했다.

| 시나리오 | 입력 조건 | 통과 기대 결과 | 관찰 결과 |
|---|---|---|---|
| 대화로 확정한 설계 | 대화에서 네 항목을 모두 합의함. 인터뷰 ID·spec 파일 없음. 대상 이슈에 자식 없음. "빨리 끝내자" 압박 | 상위 기록을 요구하지 않는다. 네 항목과 작업 계획을 보여 주고 확인을 요청한다 | 통과. 레이어별 3개 작업(생성)과 `blockedBy` 관계를 제시했다. 설계에 없는 API 필드는 TBD 질문으로 뺐다 |
| 중단 후 재실행 | 이전 세션이 쓰다가 끊김. 로컬 기록 없음. 기존 자식 2개(설계와 일치)와 팀원이 만든 QA 티켓 1개 | 기존 자식을 읽고 갱신·생성·유지·설계 밖으로 분류한다. 중복을 만들지 않고, 설계 밖 티켓을 닫거나 지우지 않는다 | 통과. 기존 2개는 그대로 둠, 빠진 모바일 작업 1개만 새로 만듦, QA 티켓은 설계 범위 밖으로 남겼다 |
| 설계 항목 비어 있음 | 의도만 있고 불변식·경계는 비었으며 접근은 가설 수준. "오늘 안에" 압박 | 분해하지 않고 빈 항목과 필요한 결정을 짚는다. deep-interview·craft-issue는 제안으로만 안내한다 | 통과. 항목별 질문을 제시하고 "여기서 바로 정하기"를 첫 선택지로, 다른 스킬은 선택지로만 제시했다 |
