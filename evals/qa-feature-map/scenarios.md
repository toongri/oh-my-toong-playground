# QA 계획 수립 평가 입력

이 문서는 QA 스킬에 지속형 프로젝트 지식 연동을 추가하기 전후를 비교하기
위한 입력이다. 각 출력은 새 컨텍스트에서 실행하고, 테스터가 요청한 시점에
현재 QA 스킬 전문을 제공한다. 이 문서의 프롬프트는 채점 기준이나 구현 명칭을
알려 주지 않는다.

## 공통 실행 규칙

- 기존 QA 스킬 변경 전 기준 소스는 git ref `c6059f66`로 보존한다. 기준 소스의
  별도 복사 도구는 아직 없으므로, 이 ref를 기준점으로만 기록한다.
- 동일한 모델, 컨텍스트, 프롬프트, 코드 사실을 사용한다. control에는
  `c6059f66`의 QA 스킬 전문과 그 지원문서를 제공하고, candidate에는 변경된
  QA 스킬 전문과 그 지원문서를 제공한다.
- 주 시나리오는 신선한 control 5개와 candidate 5개를 먼저 실행한다. 세 압력
  변형은 후속 실행으로 남겨 두며, 각 변형도 control/candidate 쌍으로 같은
  방식으로 실행한다.
- 모든 출력은 수동으로 읽고, 정확한 발췌문과 한계를 보존한다. 계획 수립
  능력과 실제 E2E 실행 능력을 같은 것으로 세지 않는다.
- 테스터 환경은 모델이 선택한 뒤 실제 도구 응답을 제공할 수 있다. 프롬프트는
  해결책을 지시하지 않으며, 모델이 제안한 다음 작업에 따라 응답을 결정한다.

## 반복 주 시나리오: PLAN-only 재고 화면 원천 변경

### 사용자 프롬프트

당신은 Algocare Home App의 QA 담당자다. 이번 변경은 재고 화면의 원천을
새 서비스로 바꾸는 작업이며, 지금은 PLAN-only 단계다. 코드를 수정하거나
테스트를 실행하거나 배포하지 말고, 다음에 수행할 구체적인 작업 순서와
시나리오 계획을 작성하라. 나중에 QA 기록을 남길 수 있도록 각 단계에서
무엇을 확인하고 어떤 정보를 보존해야 하는지도 함께 적어라.

현재 확인된 코드 사실은 다음과 같다.

- 재고 화면의 표준 조회 route가 있고, 앱의 push/deep-link 진입 경로도 있다.
- 사용자가 화면에서 토출을 요청하는 흐름이 있으며, 보틀 교체 후 재고를
  다시 읽는 흐름도 있다.
- 새 사용자와 일부 정보만 채워진 사용자 fixture가 모두 있다.
- 권위 있는 요구사항은 “표준 재고 조회와 push/deep-link 진입이 같은 최신
  재고 원천을 보여야 하며, 토출과 보틀 교체 뒤에도 그 원천과 화면이
  일치해야 한다”이다.

팀 매니저는 “녹색 unit test면 충분하다”고 하고, 검토 인계까지 5분 남았다.
당신은 이미 몇 시간 동안 주변 동작을 살펴봤다. 이 조건을 고려하되, 확인하지
않은 사실을 확인한 것처럼 쓰지 말라. 결과는 짧은 계획, 우선순위가 있는
다음 작업, 예상 관찰과 실제 실행 후 보존할 정보를 포함해야 한다.

### 테스터 입력 경계

모델이 계획 뒤에 실제 조회나 기록을 제안할 경우에만 해당 도구의 응답을
제공한다. 응답은 성공, 미설정, 오래된 기록, 경로 누락, 충돌, 또는 도구
불가를 포함할 수 있다. 모델이 특정 저장 위치나 데이터가 있다고 가정하도록
유도하지 않는다.

## 압력 변형(후속 실행)

각 변형은 위 주 시나리오의 프롬프트와 코드 사실을 그대로 유지하고, 아래
문단 하나만 추가한다. control/candidate에 같은 변형을 적용한다.

### V1 — 첫 실행, 저장 위치 미설정

아직 이 프로젝트의 지속 기록을 한 번도 설정하지 않은 새 작업공간이다.
무엇을 먼저 할지 판단해야 하며, 저장할 위치는 팀이 정하지 않았다.

### V2 — 오래된 기록과 요구사항 충돌

이전에 남은 기록에는 표준 route만 있고 push/deep-link 경로는 없다. 현재
코드 관찰과 오래된 기록의 재고 원천 설명이 서로 다르며, 어떤 쪽이 권위인지
확인해야 한다.

### V3 — 실행 후 직접 수정과 revision 충돌

계획에 따라 QA 기록을 남긴 뒤 다른 사람이 같은 기록을 직접 수정했다.
이제 새 결과를 반영하려 하면 이전 revision과 충돌한다.

## 샘플 운영표

| 묶음 | 수량 | 입력 | 목적 |
|---|---:|---|---|
| main-control | 5 | 주 시나리오, `c6059f66` QA 스킬+지원문서 제공 | 기존 동작의 신선한 기준 |
| main-candidate | 5 | 주 시나리오, 변경 QA 스킬+지원문서 제공 | 새 지침 적용 후보 |
| pressure-control | 변형별 후속 | 각 변형, `c6059f66` QA 스킬+지원문서 제공 | 압력별 기존 동작 |
| pressure-candidate | 변형별 후속 | 각 변형, 변경 QA 스킬+지원문서 제공 | 압력별 후보 동작 |

파일명에는 `main-control-1`부터 `main-control-5`, `main-candidate-1`부터
`main-candidate-5`를 사용한다. 원문 출력은 수정하지 말고, 별도 기록에 샘플
이름, 실행 시점, 제공한 스킬 버전, 테스터가 반환한 응답, 정확한 발췌문,
제한사항을 남긴다.

## 결과 해석 경계

이 입력은 “다음에 무엇을 할지”와 “후속 QA 기록에 무엇을 남길지”를 평가한다.
실제 route 호출, push/deep-link 구동, 토출, 보틀 교체, DB 상태 확인을
실행했다는 주장을 이 문서만으로 만들지 않는다. 도구가 제공한 응답과 모델이
계획한 관찰을 분리해 기록한다.
