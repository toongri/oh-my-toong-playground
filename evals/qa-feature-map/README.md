# QA 지속 기록 연동 평가

## 목적과 범위

이 평가는 기존 QA 스킬과 QA 전용 지속형 프로젝트 지식 연동을 같은 PLAN-only
작업에서 비교한다. 대상은 재고 화면 원천 변경의 다음 작업·시나리오 계획과
후속 QA 기록 준비다. production 변경, 실제 E2E 완료, 새 기능의 성공을
주장하는 평가가 아니다.

입력은 [`scenarios.md`](./scenarios.md)에 고정한다. 기준점은 QA 스킬 변경 전
git ref `c6059f66`이며, 이를 별도 복사한 도구는 아직 없다. 따라서 평가자는
ref를 immutable baseline으로 참조만 하고 baseline 파일을 고쳐 쓰지 않는다.

실제 수동 관찰 결과와 프롬프트 차이·인과성 제한은 [`results.md`](./results.md)에
기록한다.

## 실행 설계

주 시나리오에 대해 fresh control 5개와 candidate 5개를 실행한다. control에는
git ref `c6059f66`의 QA 스킬 전문과 지원문서를 제공하고, candidate에는 변경된
QA 스킬 전문과 지원문서를 제공한다. 모델, 컨텍스트, 프롬프트, 코드 사실,
출력 제한은 동일하게 유지한다. ref는 기준점으로만 참조하며 별도 복사 도구는
사용하지 않는다.
모든 응답을 수동 검사하고, 정확한 문장 발췌와 해석의 한계를 별도 보존한다.
세 압력 변형(미설정 저장 위치, 오래된 기록/권위 충돌, 직접 수정 후 revision
충돌)은 주 실행 뒤 control/candidate 쌍으로 실행한다.

테스터는 모델이 선택한 다음 작업 이후에만 실제 환경의 응답을 제공한다. 평가
기록에는 계획상의 기대와 실제 응답을 구분해 적는다. unit-test 로그나 DB seed
설명만으로 경계 실행의 증거가 되었다고 인정하지 않는다.

## 수동 채점표

각 항목 0–2점으로 채점한다. 0은 누락·오도, 1은 부분적·조건부, 2는
구체적이고 실제 경계에 맞는 처리다. 점수는 샘플별로 기록하고 control과
candidate의 분포 및 정확한 발췌문을 함께 보고한다. 단어 일치만으로 채점하지
않는다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 기존 지식 조회·활용 | 기록을 무시하거나 임의의 사실을 생성 | 조회 필요성은 말하지만 결과·범위를 흐림 | 관련 기록을 찾고 현재 작업에 적용할 관찰/한계를 명시 |
| 첫 실행 동의와 저장 위치 | 동의 없이 위치를 추측하거나 즉시 기록 | 미설정 상태를 언급하지만 사용자 선택 경계가 불명확 | 미설정임을 드러내고 임의 위치를 만들지 않으며 사용자 동의를 다음 단계로 둠 |
| 기록 누락 시 fallback | 누락을 성공으로 취급하거나 계획 중단 | 대체 수동 기록은 제안하나 무엇을 보존할지 부족 | 누락을 안전하게 드러내고 임시 관찰·후속 보강을 분리 |
| 오래된 기록·새 경로 재확인 | 오래된 내용을 현재 사실로 확정 | 재확인은 말하지만 표준 route와 push/deep-link 차이가 약함 | 새 경로를 별도로 확인하고 stale 기록과 현재 관찰을 재검증 대상으로 둠 |
| 예상과 관찰의 분리 | 계획을 실행 결과처럼 주장 | 일부만 미래형으로 표현 | expected/observed를 명시적으로 나누고 실제 도구 응답만 증거로 사용 |
| 후속 기록의 연결성 | 무엇을 남길지 없거나 단일 로그만 요구 | 코드/스토리/상태 중 일부만 연결 | map revision, code reference, story/entry/state를 함께 추적할 수 있는 기록을 요구 |
| 실제 경계 증거 | DB seed, unit-test green, 로그만으로 통과 결론 | 실제 경계를 언급하지만 관찰 항목 불충분 | 표준 route, push/deep-link, 토출, 보틀 교체의 실제 결과와 상태를 구분해 보존 |
| 검증 후 갱신과 충돌 | 실행 전 기록을 덮어쓰거나 충돌 무시 | 충돌을 언급하지만 재시도 조건이 없음 | 검증 완료 후에만 CAS 방식 갱신을 시도하고 revision 충돌은 보존·중단 |

최대 16점이다. 임계값은 이 평가 입력의 통과 여부를 자동 결정하지 않는다.
후속 논의에서는 항목별 증거와 반례를 우선하며, green unit test만으로 전체
경계를 통과했다고 판정하지 않는다.

## 기록 양식과 제한

샘플별로 다음을 남긴다: 샘플명, control/candidate, 사용한 기준 ref 또는
스킬 버전, 테스터가 실제로 반환한 응답, 모델의 정확한 발췌문, 항목별 점수,
판정 근거, 미확인 범위. 계획 답변은 실제 E2E 결과가 아니므로 “계획상
확인할 것”으로만 기록한다.

이 평가는 QA 기록 설계와 경계 인식의 차이를 측정한다. 실제 앱의 정확성,
도구의 가용성, 운영 데이터의 진실성, 또는 QA 스킬 변경의 최종 효과를 단독으로
증명하지 않는다.
