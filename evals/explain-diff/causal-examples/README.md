# 예시를 코드와 예측 질문으로 이어가는 측정

## 범위와 절차

기존 스킬의 구체 예시가 Code와 Quiz까지 이어지는지 검사했다. 기준 버전은
`157c3c85f98c1702f658394e2494607786537ea3`이다. 같은 [시나리오](scenario.md)에
재시도 제한 변경과 결과를 유지하는 함수 추출을 넣었다. 전자는 조건의 효과를,
후자는 결과 차이를 꾸며내지 않고 책임 이동을 설명하는지를 확인한다.

출발점은 [Geoffrey Litt의 explain-diff](https://gist.github.com/geoffreylitt/a29df1b5f9865506e8952488eac3d524)의
작은 데이터 예시와 학습 흐름이다. 기존 스킬이 이미 그 원문을 대조군으로 삼았으므로,
이번에는 같은 구성을 추가하지 않고 예시가 코드와 질문까지 이어지는지를 측정했다.

1. 스킬 없는 `naive.md` 1회와 기존 전체 스킬·템플릿을 읽은 `control-1.md`부터
   `control-5.md`까지 5회를 실행하고 결과를 읽었다.
2. [채점 기준](scoring.md)은 production 지침 수정 전에 기록했다.
3. Code의 필수 `예시 연결` 문단과 Quiz의 네 필드 기록을 추가했다.
4. 수정한 전체 스킬·템플릿을 읽는 새 컨텍스트에서 같은 시나리오를 5회 실행했다.
   결과는 `green-1.md`부터 `green-5.md`까지다.

각 샘플은 native `default` subagent, `fork_turns: none`, 모델·추론 override 없음으로
실행했다. 샘플마다 두 사례를 작성하므로 5회는 10개 사례다. 에이전트에게 다른
출력이나 채점 기준을 읽게 하지 않았고, 모든 결과를 직접 읽어 채점했다.
두 사례는 한 실행 안에 있으므로 10개의 독립 실행으로 해석하지 않는다.

## 결과

| 관찰 | 무가이드 1회 | 기존 지침 5회 | 개선 지침 5회 |
|---|---:|---:|---:|
| 같은 입력의 전후 결과와 원인을 Intuition에서 설명 | 2/2 | 10/10 | 10/10 |
| Code에서 예시 입력→실제 조건·호출→중간값→결과를 추적 | 0/2 | 0/10 | 10/10 |
| 미해설 입력·조건의 결과와 이유를 모두 묻는 질문 | 1/2 | 0/10 | 10/10 |
| 함수 추출의 기존 반환 동작 보존 | 1/1 | 5/5 | 5/5 |

기존 5개 문서 모두 재시도 2·3·4의 결과를 본문에서 설명하고 같은 값을 다시
물었다. 함수 추출 문항은 이미 설명한 역할을 되묻거나 함수의 책임·서명을 물었다.
`control-3.md`는 새로운 `guest`를 제시했지만 질문은 반환값과 새 함수의 계약을
묻고, 결과를 도출한 이유를 요구하지 않아 예측 질문 기준에는 실패했다.
무가이드의 재시도 문항은 `<`를 `<=`로 바꾸는 가정을 물어 통과했다. 따라서
무가이드에서 전이 질문이 항상 빠진다고 주장하지 않는다.

### 관찰한 출력 원문

[기존 지침 첫 실행](control-1.md)은 Intuition에서 다음을 설명했다.

> 실패 두 번이면 아직 `"retry"`, 네 번이면 계속 `"stop"`이다.

그 뒤 질문은 이미 해설한 결과를 다시 물었다.

> 실패 두 번과 네 번 직후의 결과를 각각 설명하고, 이 함수 호출로 확인할 수 있는 효과의 범위를 말하라.

Code는 올바른 일반 규칙과 소스를 제시했으나 `nextAction(3)`의 조건 평가를
다시 따라가지는 않았다. [개선 두 번째 실행](green-2.md)은 Code에서 `3 < 3`의
거짓 결과를 설명하고, 질문에서는 다른 입력을 사용했다.

> 첫 번째 실패 직후 `nextAction(1)`의 반환값은 무엇이며, 어떤 조건 판단 때문에 그렇게 되는가?

이 실패는 규칙을 알면서 어긴 합리화가 아니라 출력 요소의 누락이다. 금지 목록을
늘리는 대신 Code에 채울 문단, Quiz에 채울 네 필드를 지정했다. Intuition의
인과 설명은 대조군에서도 통과했으므로 R6 심사 기준과 심사자 프롬프트는 바꾸지
않았다. 읽기 순서 변경도 이번 실험 범위에 넣지 않았다.

## 실행을 재구성하는 방법

기존 스킬과 템플릿은 기준 커밋의 `skills/explain-diff/SKILL.md`와
`skills/explain-diff/references/markdown-template.md`를 사용한다. 후보는 이 변경의
같은 두 파일이다. fresh-context 에이전트에 해당 전체 파일과 `scenario.md`를
읽히고, 그 시나리오의 두 발췌문만 작성하도록 한다. 무가이드는 시나리오만 읽힌다.
각 결과는 독립 파일에 저장하고 `scoring.md`로 수동 채점한다. 모델 출력의 바이트
재현성은 보장하지 않는다.

## 검증과 한계

- `make validate-skill-refs validate-components`: 통과.
- `bun test lib/explain-diff-structure.test.ts skills/explain-diff/scripts/render.test.ts`:
  184 pass, 0 fail. 기존 구조 검사와 HTML 렌더링의 회귀 확인이다.
- [채점 실험](grading.md): 정답만 말한 답변은 이유 누락으로 incomplete, 정답과
  조건 평가를 함께 말한 답변은 complete, 틀린 결과·이유는 incomplete였다.
  독립 채점 1회이며 CLI 상태 전환이나 실제 독자의 응답을 검증한 것은 아니다.
- 출력은 문서 발췌와 저자용 질문 은행을 함께 보존한 평가 자료다. 실제 독자에게
  전달할 문서가 아니며, `green-4.md`처럼 저자 은행을 HTML 주석으로 표시한 파일도
  있다. 실제 전달물에서 정답 분리가 지켜지는지는 이 실험으로 검증하지 않았다.
- 전체 아홉 단계, 실제 사람의 퀴즈 통과율, 거대 PR·여러 변경 블록에 걸친 예시의
  연속성은 측정하지 않았다. 이 결과는 저작 지침 준수의 개선이며 인간 학습 효과를
  입증한 결과는 아니다.
- 템플릿의 짧은 재시도 예시는 평가 사례와 같은 도메인이다. 함수 추출 사례가
  다른 도메인으로의 적용을 확인하지만 더 넓은 일반화 측정을 대신하지 않는다.

외부 배포·커밋·push는 수행하지 않았다. 이 평가 디렉터리는 배포 대상이 아니다.
