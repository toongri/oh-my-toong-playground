## 한 줄 요약

이미 CLI 플래그로 막아둔 "워커의 서브에이전트 스폰"을, **프롬프트 문장으로도 한 번 더 막은** 커밋이다. 동시에 예전 프롬프트에 남아 있던 "스폰해도 된다"는 **반대 방향 지시를 삭제**했다.

---

## 1. 먼저 알아야 할 것: 잡(job)과 워커(worker)

이 저장소의 몇몇 스킬은 자기가 직접 일하지 않고, **외부 CLI를 자식 프로세스로 띄워서** 일을 시킨다. 이 구조를 이 저장소에서는 **잡(job)** 이라 부르고, 띄워진 자식 프로세스 하나하나를 **워커(worker)** 라 부른다.

이번 커밋이 건드린 스킬 4종이 전부 그 구조다.

| 스킬 | 워커(멤버) | 실제로 띄우는 CLI | 하는 일 |
|---|---|---|---|
| `agent-council` (자문 위원회) | `claude`, `gpt`, `glm` | `claude -p`, `codex exec`, `opencode run` | 같은 질문에 서로 다른 모델이 독립 의견을 냄 |
| `design-review` (설계 리뷰) | `gpt` | `codex exec` | 설계안을 리뷰 |
| `diagnose` (원인 진단) | `hephaestus` | `opencode run` | 코드를 읽고 근본 원인을 지목 |
| `slides-review` (슬라이드 리뷰) | `gemini` | `gemini` | HTML 발표자료의 시각 디자인을 리뷰 |

즉 부모 세션이 워커 N개로 **한 번 부채꼴로 퍼진다(팬아웃, fan-out)**.

문제는 이거다. 워커도 결국 코딩 CLI라서, **워커가 또 자기 밑으로 서브에이전트를 스폰할 수 있다.** 그러면 팬아웃 밑에 팬아웃이 생긴다. 부모는 이걸 예산에 넣은 적이 없고, 리뷰 프롬프트가 의도한 적도 없는 산출물이 섞여 돌아온다. 이 저장소 설정 파일은 그 이유를 이렇게 적어 놓았다 (`skills/design-review/design-review.config.yaml:20-21`):

> "Spawning is a second fan-out beneath this one — unbudgeted cost, and counsel no review prompt shaped."
> (스폰은 이 팬아웃 밑의 두 번째 팬아웃이다 — 예산에 없는 비용이고, 어떤 리뷰 프롬프트도 형태를 잡아준 적 없는 조언이다.)

## 2. 이 커밋의 위치 — 4연작 중 마지막

이 커밋은 혼자 있는 게 아니라, 같은 날 연달아 들어간 4개 커밋의 **마지막 조각**이다.

```
36f550d5  feat: 잡 워커 서브에이전트 차단 축 추가       ← 엔진 (lib/generic-job.ts)
4d81c763  feat: design-review·diagnose 차단 배관 이식   ← 배관 (각 스킬 job.ts)
2bd75617  chore: 잡 config 4종 차단 선언 통일           ← 선언 (각 스킬 *.config.yaml)
1c4e0292  chore: 잡 워커 프롬프트에 단독 수행 지시 추가  ← ★ 이 커밋 (프롬프트)
```

앞의 셋은 **기계적 차단**을 만들었다. 흐름은 이렇다.

```
*.config.yaml              job.ts                    lib/generic-job.ts
settings.deny.subagents:   extractDenySubagents()    buildAugmentedCommand()
        true          →    로 읽어서           →      가 CLI별 플래그로 번역
                           assertDenyEnforceable()
                           로 집행 가능 여부 검사
```

번역 결과는 CLI마다 다르다 (`lib/generic-job.ts:410-470`):

| 워커 CLI | 붙는 것 | 효과 |
|---|---|---|
| `codex` | `-c agents.enabled=false` | 세션에서 스폰 툴 설명 자체를 제거 — 프롬프트가 시켜도 스폰할 수단이 없음 |
| `claude` | `--settings '{"permissions":{"deny":["Agent","Task"]}}'` | 스폰 툴을 이름으로 deny → 툴 목록에서 사라짐 |
| `opencode` | `OPENCODE_CONFIG_CONTENT`의 `permission.task: deny` | 동일 |
| `gemini` | **없음** | 레버 자체가 존재하지 않음 |

마지막 줄이 이 커밋의 존재 이유다. 엔진에는 이런 상수가 박혀 있다 (`lib/generic-job.ts:157`):

```ts
const ENFORCEABLE_CLI_TYPES = ["codex", "claude", "opencode"];
```

**gemini는 여기 없다.** 그래서 `slides-review`는 `settings.deny`를 아예 선언하지 못한다 — 선언하면 `assertDenyEnforceable`이 `start`를 exit 1로 죽인다("선언 가능 = 집행 가능" 불변식). 결과적으로 gemini 워커에게 남은 차단 수단은 **프롬프트 문장 하나뿐**이다.

## 3. 실제 변경 — 세 가지 패턴

7개 파일이지만 패턴은 셋뿐이다.

### 패턴 A — 순수 추가 (4개 파일, +1줄씩)

기존 제약 목록에 한 줄을 끼워 넣었다.

`skills/agent-council/prompts/codex.md`, `glm.md`:
```diff
 Constraints:
+- Argue your perspective alone — do not spawn any subagents
 - Focus on implementation practicality — can this actually be built as described?
```

`skills/agent-council/prompts/default.md`:
```diff
 ## Response Discipline
 
+- Argue your perspective alone — do not spawn any subagents.
 - Ground every claim in the context provided by the caller. Do not invent facts.
```

`skills/slides-review/prompts/gemini.md`:
```diff
 ## Rules
+- Review this deck alone — do not spawn any subagents
 - Maximum 10 directives, prioritized by visual impact
```

> **디테일 하나**: `Constraints:` / `## Rules` 목록의 다른 항목들은 마침표가 없고, `## Response Discipline` 목록의 항목들은 마침표가 있다. 추가된 줄도 **각 목록의 기존 습관을 그대로 따랐다**. 문서 스타일을 헤치지 않는 최소 개입이다.

### 패턴 B — 문장 교체 (3개 파일) ← **여기가 진짜 핵심**

`skills/agent-council/prompts/gpt.md`, `skills/design-review/prompts/default.md`, `skills/diagnose/prompts/default.md` 세 파일에는 **원래 이런 문장이 있었다**:

```diff
-- Deliver one complete response in a single turn. If you delegate or spawn sub-work,
-  run it in the foreground and wait for it to finish before answering — never pause
-  mid-turn or split your answer across multiple turns expecting to be resumed.
+- Work this review alone — do not spawn any subagents.
+- Deliver one complete response in a single turn. Do not pause mid-turn or split your
+  answer across multiple turns expecting to be resumed.
```

삭제된 조건절을 다시 읽어 보자.

> "**If you delegate or spawn sub-work, run it in the foreground and wait for it to finish**"
> (위임하거나 하위 작업을 스폰한다면, 포그라운드로 돌리고 끝날 때까지 기다려라)

이건 스폰을 **허용**하는 문장이다. 다만 "비동기로 던져놓고 턴을 끊지는 말라"는 조건을 달았을 뿐이다. 원래 이 문장의 목적은 **스폰 금지가 아니라 턴 분할 방지**였다.

이제 앞선 커밋들이 `agents.enabled=false` 같은 플래그로 스폰 능력 자체를 제거했다. 이 문장을 그대로 두면 프롬프트는 존재하지 않는 능력을 쓰라고 안내하는 셈이 된다 — 워커는 없는 툴을 찾다가 헛돌거나, 지시가 서로 모순된다고 판단하게 된다.

그래서 이 커밋은 **한 문장을 두 문장으로 쪼갰다**:

- 조건절을 떼어내고 → 반대 방향의 **금지**로 교체 (`Work this review alone — do not spawn any subagents.`)
- 남은 본래 목적(턴 분할 방지)은 **독립된 문장으로 보존** (`Do not pause mid-turn or split your answer...`)

`+3 −3`이 아니라 `+2 −1`인 이유이자, 이 커밋이 단순 추가가 아닌 이유다. **기계 차단과 프롬프트가 서로 반대를 말하는 상태를 해소한 것이다.**

### 패턴 C — 역할에 맞춘 문구 변형

같은 뜻인데 문장의 앞부분이 파일마다 다르다.

| 파일 | 문구 | 그 워커의 역할 |
|---|---|---|
| `agent-council/*` | **Argue** your perspective alone | 자기 관점을 *변론*함 |
| `design-review/default.md` | Work this **review** alone | *리뷰*를 수행함 |
| `diagnose/default.md` | Work this **analysis** alone | *분석*을 수행함 |
| `slides-review/gemini.md` | **Review this deck** alone | *덱을 리뷰*함 |

복붙이 아니라 각 프롬프트의 페르소나에 맞춘 것이다. 뒷부분 `— do not spawn any subagents`는 전부 동일하다.

## 4. 프롬프트 파일이 실제로 어떻게 선택되는가

`prompts/` 안의 파일 이름은 장식이 아니다. `lib/worker-utils.ts:100-137`의 `assemblePrompt()`가 이렇게 고른다:

```
1) prompts/{멤버이름}.md   ← 있으면 이것
2) prompts/default.md      ← 없으면 이것
3) 둘 다 없으면 원본 프롬프트만 (구조화 없음)
```

`{멤버이름}`은 config의 `name:` 값이다. 그래서:

| config의 멤버 이름 | 실제로 읽히는 파일 |
|---|---|
| `agent-council`의 `claude` | `prompts/claude.md` |
| `agent-council`의 `gpt` | `prompts/gpt.md` |
| `agent-council`의 `glm` | `prompts/glm.md` |
| `design-review`의 `gpt` | `gpt.md`가 없으므로 → `prompts/default.md` |
| `diagnose`의 `hephaestus` | `hephaestus.md`가 없으므로 → `prompts/default.md` |
| `slides-review`의 `gemini` | `prompts/gemini.md` |

### `default.md`는 역할이 둘이다

여기가 헷갈리기 쉬운 지점이다. `default.md`는 **두 개의 완전히 다른 상황**에서 쓰인다.

1. **워커의 폴백 역할 프롬프트** — 위 표처럼, 자기 이름 파일이 없는 멤버가 읽는다. (`design-review`, `diagnose`가 이 경우)
2. **in-session 폴백 페르소나** — 워커를 아예 **띄우지 못했을 때**, 부모 세션이 직접 이 파일을 읽고 그 페르소나가 되어 혼자 처리한다. `SKILL.md`에 명시돼 있다 (`skills/diagnose/SKILL.md:45`):

   > "If `start` exits non-zero or `$JOB_DIR` is empty, fall back to in-session analysis (READ `prompts/default.md`)."

그래서 `default.md`에 들어간 "do not spawn any subagents"는 **자식 워커에게도, 폴백으로 직접 일하는 부모 세션에게도** 걸린다. 한 줄이 두 경로를 덮는다.

## 5. 커버리지 정리 — 그리고 남은 빈틈 하나

각 워커가 실제로 받는 방어를 정리하면:

| 워커 | CLI 차단 (`deny.subagents`) | 프롬프트 차단 (이 커밋) | 결과 |
|---|---|---|---|
| `design-review` / `gpt` (codex) | ✅ `subagents: true` → `agents.enabled=false` | ✅ `default.md` | 이중 방어 |
| `diagnose` / `hephaestus` (opencode) | ✅ `subagents: true` → `permission.task: deny` | ✅ `default.md` | 이중 방어 |
| `slides-review` / `gemini` | ❌ 레버 없음 (선언하면 `start` 실패) | ✅ `gemini.md` | **프롬프트가 유일한 방어** |
| `agent-council` / `gpt` (codex) | ❌ config에 `subagents` 선언 없음 | ✅ `gpt.md` | 프롬프트만 |
| `agent-council` / `glm` (opencode) | ❌ 동일 | ✅ `glm.md` | 프롬프트만 |
| `agent-council` / `claude` | ❌ 동일 | ❌ **`claude.md` 미수정** | **둘 다 없음** |

### 확인된 사실: `agent-council`은 `deny.subagents`를 선언하지 않았다

`skills/agent-council/council.config.yaml`에는 `settings.deny.skills`(40개 스킬 목록)만 있고 `subagents:` 키가 없다. `extractDenySubagents()`는 `deny.subagents === true`일 때만 참을 반환하므로(`lib/generic-job.ts:256-259`), 위원회 멤버 3명에게는 **CLI 레벨 스폰 차단이 전혀 걸리지 않는다.** 형제 스킬인 `design-review`·`diagnose`가 같은 날 `subagents: true`를 선언한 것과 대조된다.

즉 `agent-council`에서는 이 커밋의 프롬프트 문장이 **유일한 차단 수단**이다.

### 확인된 사실: `prompts/claude.md`만 빠졌다

`agent-council/prompts/`에는 5개 파일이 있는데 이 커밋은 4개(`codex.md`, `default.md`, `glm.md`, `gpt.md`)만 고쳤다. `claude.md`는 그대로다. 현재 내용 전문은 이렇다:

```
Constraints:
- Provide your independent opinion — do not hedge or try to anticipate what others might say
- Support every recommendation with specific reasoning
- If you disagree with the premise of the question, say so explicitly
- Structure your response with clear sections: Position, Reasoning, Risks, Recommendation
```

스폰 관련 문장이 하나도 없다. 그런데 `council.config.yaml:21`의 멤버 `name: claude`는 `assemblePrompt()`에 의해 정확히 이 파일을 읽는다 — `default.md`로 폴백하지 않는다.

**따라서 `agent-council`의 claude 멤버는 CLI 차단도 프롬프트 차단도 받지 않는 유일한 워커다.** 반대로 `codex.md`는 수정됐지만 현재 config에 `codex`라는 이름의 멤버가 없어서(codex CLI를 쓰는 멤버의 이름은 `gpt`다) 지금은 읽히지 않는 파일이다. 손이 한 칸씩 밀린 모양새다.

> 이 문서는 커밋을 설명할 뿐 고치지는 않았다. 실제로 막으려면 `claude.md`에 같은 줄을 추가하거나, 더 근본적으로 `council.config.yaml`에 `deny.subagents: true`를 선언하는 쪽이다. 후자는 멤버 3종의 CLI가 모두 `ENFORCEABLE_CLI_TYPES`에 들어 있어 집행 가능하다.

## 6. 이 커밋에서 가져갈 교훈

1. **기계적 차단과 프롬프트는 같은 방향을 봐야 한다.** 플래그로 능력을 없앴는데 프롬프트가 "써도 된다"고 하면, 그건 중복이 아니라 모순이다. 패턴 B가 그걸 지웠다.
2. **집행 불가능한 경계에서는 프롬프트가 유일한 방어다.** gemini에는 레버가 없으므로 `gemini.md`의 한 줄이 전부다. "프롬프트는 어차피 안 지켜지니 무의미"가 아니라, 그거라도 있어야 하는 자리가 있다.
3. **한 문장에 목적이 두 개 섞여 있으면 쪼개라.** 원래 문장은 "턴 분할 금지"가 목적인데 조건절이 "스폰 허용"을 부수적으로 뜻하고 있었다. 정책이 바뀌자 그 부수 의미가 발목을 잡았다.
4. **횡단 변경의 커버리지는 파일 개수가 아니라 실행 경로로 세라.** 4/5 파일을 고쳤지만, 빠진 1개가 하필 실제 실행되는 멤버의 파일이고 고친 1개는 실행되지 않는 파일이었다.

**Q7.** (심화) `agent-council`의 claude 멤버는 이 커밋 이후에도 서브에이전트를 스폰할 수 있다. 그 이유 **두 가지**를 각각 어느 파일의 어떤 사실에 근거해 말할 수 있는가?

**Q8.** (심화) `agent-council/prompts/codex.md`는 이 커밋에서 수정됐지만, 현재 config 기준으로는 실행 시 읽히지 않는다. 왜인가?

---

### 정답

**A1.** 0개. 7개 전부 마크다운 프롬프트 파일이다. 이 커밋은 **동작 로직이 아니라 워커에게 주는 지시문만** 바꿨다는 뜻이다. 기계적 차단은 이미 앞선 세 커밋(`36f550d5`, `4d81c763`, `2bd75617`)이 코드와 config에 넣어 놓았다.

**A2.** **허용**한다 — "만약 스폰한다면, 포그라운드로 돌려라"라는 조건부 허가다. 이 문장의 원래 목적은 스폰 금지가 아니라 **턴 분할 방지**였다. 앞선 커밋들이 `agents.enabled=false` / `permission.task: deny` 등으로 스폰 능력 자체를 제거했으므로, 이 문장을 남겨두면 프롬프트가 존재하지 않는 능력을 쓰라고 안내하게 된다. 그래서 조건절만 금지문으로 교체하고, 본래 목적인 턴 분할 방지는 별도 문장으로 보존했다.

**A3.** `start`가 exit 1로 실패한다. `lib/generic-job.ts:157`의 `ENFORCEABLE_CLI_TYPES`는 `["codex", "claude", "opencode"]`이고 gemini는 없다. `assertDenyEnforceable()`이 "deny가 선언됐는데 집행 레버가 없는 멤버가 있다"며 잡 디렉터리 생성 전에 중단시킨다. **"선언 가능 = 집행 가능"** 불변식 — 막히지 않는 채로 조용히 도는 것보다 아예 안 도는 쪽을 택한 설계다.

**A4.** `lib/worker-utils.ts:100-137`의 `assemblePrompt()` 폴백 규칙. `prompts/hephaestus.md`를 먼저 찾고 없으면 `prompts/default.md`를 읽는다. 그래서 `default.md` 한 파일이 hephaestus 워커의 역할 프롬프트가 된다.

**A5.** (1) **스폰된 워커** — `gpt` 멤버가 자기 이름 파일이 없어 `default.md`를 역할 프롬프트로 읽는다. (2) **부모 세션 자신** — `start`가 실패하거나 `$JOB_DIR`이 비면 `SKILL.md:35`의 지시대로 부모가 `default.md`를 읽고 그 페르소나가 되어 in-session으로 리뷰를 수행한다.

**A6.** 각 프롬프트의 페르소나 역할에 맞췄기 때문이다. 위원회 멤버는 관점을 *변론(argue)* 하고, diagnose 워커는 *분석(analysis)* 을 수행하고, slides-review 워커는 *덱을 리뷰* 한다. 뒷부분 `— do not spawn any subagents`는 4곳 전부 동일하다. 앞부분만 문맥에 맞춘 것이다.

**A7.**
1. **CLI 레벨 차단 없음** — `skills/agent-council/council.config.yaml`의 `settings.deny`에는 `skills:` 목록만 있고 `subagents:` 키가 없다. `extractDenySubagents()`는 `deny.subagents === true`일 때만 참이므로 `denySubagents = false`가 되고, `buildAugmentedCommand()`가 스폰 차단 플래그를 붙이지 않는다.
2. **프롬프트 레벨 차단 없음** — 멤버 이름이 `claude`이므로 `assemblePrompt()`가 `prompts/claude.md`를 읽는데(`default.md`로 폴백하지 않는다), 이 커밋은 그 파일을 고치지 않았다. 파일 전문에 스폰 관련 문장이 없다.

**A8.** `assemblePrompt()`는 `prompts/{멤버이름}.md`를 찾는데, `council.config.yaml`에 `codex`라는 **이름**의 멤버가 없기 때문이다. codex CLI를 쓰는 멤버는 있지만 그 이름은 `gpt`이고(`command: codex exec`), 따라서 `prompts/gpt.md`가 읽힌다. `codex.md`는 이름이 `codex`인 멤버가 config에 추가될 때만 살아나는 파일이다.
