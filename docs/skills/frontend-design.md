# 프론트엔드 디자인 스킬

프론트엔드 디자인 스킬은 웹 UI를 설계·구현하고, 렌더링된 결과를 독립적으로 검증하는 경로를 제공합니다. `frontend`가 디자인 원칙과 참고 룰셋을 요청에 맞게 라우팅하고, `visual-qa`가 실제 화면의 완성 여부를 판정합니다.

---

## 핵심 요약

| 스킬 | 역할 한 줄 요약 | 주요 입력 | 언제 사용하나 |
|------|----------------|-----------|---------------|
| `frontend` | 네 가지 룰셋을 선택적으로 연결하는 디자인 원칙 라우터 | UI/UX 요청, 시각적 참조, 프로젝트의 `DESIGN.md` | 프론트엔드 화면을 만들거나 고치거나 감사할 때 |
| `visual-qa` | 두 독립 오라클이 렌더링 증거를 판정하는 시각 검증 게이트 | 실제 화면 캡처, 참조 이미지, 상호작용 상태, TUI 캡처 | UI 변경 후 완료 여부를 검증할 때 |

---

## 스킬 상세

### frontend

**목적**: `frontend`는 규칙을 직접 재현하는 단일 지침서가 아니라, 요청에 필요한 디자인 원칙 룰셋을 고르는 라우터입니다. 항상 가장 작은 관련 집합을 선택해 로드하고, 선택한 원칙을 `DESIGN.md`와 구현·검증 흐름에 반영합니다.

**네 가지 룰셋**:
- `design`: 시각적 취향, 브랜드 참조, 디자인 시스템과 `DESIGN.md` 계약을 라우팅합니다.
- `perfection`: 실제 브라우저 기반 성능·SEO·접근성 품질 기준을 적용합니다.
- `ui-ux-db`: 팔레트·폰트·레이아웃·도메인 UX 지침을 검색해 구체적인 선택을 돕습니다.
- `designpowers`: 페르소나, 인지·접근성 제약, 비평, 디자인 부채와 핸드오프를 설계 운영 맥락에 연결합니다.

**완료 게이트**: `frontend`가 맡은 모든 시각 작업은 `/visual-qa`의 dual-oracle 검증 게이트를 통과해야 완료입니다. 구현자의 육안 확인이나 정적 체크만으로 완료를 선언하지 않습니다.

**언제 사용하나**: 웹 UI/UX 구현·리디자인·스타일링·레이아웃·모션·접근성·성능 감사·목업 생성처럼 시각적 표면을 다루는 모든 작업에 사용합니다. 순수 백엔드·CLI·시각 출력이 없는 로직 작업에는 사용하지 않습니다.

### visual-qa

**목적**: `visual-qa`는 실제로 렌더링된 화면을 객관적 증거로 수집한 뒤, 서로 독립적인 두 개의 읽기 전용 오라클이 디자인 시스템·기능 무결성과 시각적 충실도·CJK 정밀도를 각각 검토하는 dual-oracle 검증 게이트입니다.

**검증 대상**: 웹 페이지와 컴포넌트, 반응형 뷰포트, 참조 이미지와의 일치, hover/focus/active 및 모션 상태, CJK 텍스트 클리핑, 그리고 TUI의 폭·테두리·정렬을 실제 구동 결과로 확인합니다. 필요한 경우 페이지·상태·브레이크포인트 전체를 빠짐없이 캡처합니다.

**판정 원칙**: 스크립트의 diff·폭 측정 결과는 오라클이 판단할 증거이지 최종 판정 자체가 아닙니다. 두 오라클의 독립 리뷰와 신선한 캡처 증거를 종합해 PASS·REVISE·FAIL을 내리며, 실패한 표면은 수정 후 다시 캡처하고 검증합니다.

**언제 사용하나**: UI를 새로 만들거나 변경한 뒤, 또는 페이지가 참조·디자인 의도·반응형·상호작용 상태에 맞는지 확인해야 할 때 사용합니다. 시각적 표면이 없는 순수 로직 변경에는 사용하지 않습니다.

---

## 스킬 선택 가이드

```
무엇을 하는가?
  |-- 웹 UI/UX·시각 작업을 설계·구현·감사 -> frontend
  |-- UI 변경 결과를 실제 렌더링으로 검증 -> visual-qa

frontend를 사용한 뒤:
  반드시 /visual-qa를 실행해 dual-oracle 완료 게이트를 통과합니다.
  캡처가 오래되었거나 수정이 발생하면 최신 증거를 다시 수집합니다.
```
