디스펜서 USB 고착

태블릿 앱 3.3.0 설치 뒤 CodePush 3.3.2가 적용되면서, 일부 디스펜서의 태블릿이 메인보드로 명령을 보내지 못하게 됐습니다. 받는 쪽은 정상이라 겉보기엔 멀쩡하지만 토출 버튼을 누르면 「토출 불가」가 뜹니다. 기기를 재부팅하면 풀립니다.

한눈에 보는 원인과 조치

원인. CodePush는 JS만 다시 불러오고 앱 프로세스는 그대로 둡니다. 이때 React Native가 시리얼 모듈 인스턴스를 새로 만드는데, 이 모듈에는 정리 코드(포트 닫기, 리시버 해제)가 없습니다. 이전 인스턴스가 포트를 쥔 채 남아 받기만 처리하고, 보내기는 포트를 열지 못한 새 인스턴스가 맡아 실패합니다.

조치. 3.4.0에서 리로드 직전에 정리하도록 고칩니다. APK 배포가 필요해서 CodePush로는 고칠 수 없습니다. 고착된 26대는 3.4.0 설치만으로 복구됩니다.

영향 범위

고착은 업데이트 직후 한 번에 발생했고, 이전 4주 동안은 한 건도 없었습니다.

사용자가 본 증상과 이유

화면과 와이파이는 멀쩡해서 현장에서는 기기 고장으로 보였습니다. 아래는 증상마다 앱 안에서 일어난 일입니다.

토출을 누르면 에러 코드 없이 「토출 불가」
앱이 isBooted=false로 보고 있어서 토출 명령을 아예 보내지 않습니다. 실패한 명령이 없으니 에러 코드도 없습니다.
화면 데이터와 와이파이는 정상
서버 통신은 USB와 별개라 원격 측정(telemetry)이 계속 올라옵니다.
커버 열기·닫기는 계속 기록됨
받는 길은 이전 인스턴스를 통해 살아 있습니다.
기다려도 풀리지 않고 재부팅하면 풀림
재부팅은 프로세스를 새로 만들어 시리얼 모듈 인스턴스가 다시 하나가 됩니다.

정상일 때의 구조

태블릿 앱은 시리얼 모듈을 거쳐 USB로 메인보드와 말합니다. 시작할 때 앱이 부팅 확인을 보내고 메인보드가 답하면 isBooted=true가 되어 보틀(영양제 용기)을 읽습니다.

고착된 구조

그림 1과 같은 배치에서 시리얼 모듈 칸만 둘로 나뉩니다. 보내기는 위쪽 새 인스턴스를, 받기는 아래쪽 이전 인스턴스를 지납니다.

이렇게 만들어졌습니다

  1. CodePush가 JS만 다시 불러옴프로세스는 살아 있고, 시리얼 모듈 정리 코드(포트 닫기·리시버 해제)가 없습니다.
  2. 새 시리얼 모듈 인스턴스 생성이전 인스턴스의 브로드캐스트 리시버(앱 컨텍스트에 등록)는 해제되지 않고 남습니다.
  3. 이전 리시버가 두 번째 연결을 엶새 인스턴스의 USB 권한 결과에 반응해 같은 포트를 직접 엽니다. 포트는 이전 인스턴스 차지가 됩니다.
  4. 알림이 새 JS로 도착RN 0.86에서는 리로드해도 이벤트 채널이 유지되어(BridgelessReactContext.destroy()가 아무것도 안 함) 이전 인스턴스의 알림과 「연결됨」이 새 JS에 닿습니다.
  5. 보내기만 실패하며 고정새 인스턴스는 connected=false. 부팅 확인·버전 조회를 500ms마다 보내도 거절되거나 유실되어 isBooted는 영원히 false입니다.

3.4.0의 수정

APK 배포가 필요합니다. 근본 수정 하나와 안전장치 둘로 구성합니다.

근본 수정

리로드 직전에 정리

RN이 JS를 다시 불러오기 직전에 호출하는 invalidate()에서 포트를 닫고, 리시버를 해제하고, 상태를 초기화합니다.

patches/react-native-serialport@1.3.1.patch

안전장치 1

보낸 인스턴스 표시, 연 인스턴스만 알림

브로드캐스트에 보낸 인스턴스 id를 붙여 자기 것만 전달합니다. 포트를 실제로 연 인스턴스만 「연결됨」을 알립니다.

같은 패치 파일

안전장치 2

연결됐다고 믿는데 쓰기가 코드 13이면 재연결

그 경우 연결 끊김으로 보고 다시 연결합니다. 연결 중에는 멈추지 못하던 stopUsbService()도 함께 고칩니다.

apps/dispenser/src/core-hardware/hooks/useRNserialport.ts

바꾸지 않는 것

  • 부팅 관리(boot manager)와 메시지 큐
  • 기기 id
  • 보틀 읽기 JS 로직
  • 서버, 인프라, CodePush 라이브러리

펌웨어와 에뮬레이터

  • 메인보드 펌웨어: 변경 없음. 명령이 태블릿 밖으로 나가지 않았고, 메인보드는 알림을 정상으로 보냈으며 BootManager 핸드셰이크도 있습니다.
  • 포트 닫기·다시 열기: APK 설치마다 이미 검증됨.
  • 에뮬레이터 가상 메인보드: 변경 없음 (켜진 보드에도 PROTOCOL.md의 0x01이 응답).
  • 에뮬레이터 체크리스트: 「JS 재로드 뒤 부팅」 케이스를 추가.
