# fc-feedback 뷰어 디자인 계약

이 문서는 `render.ts`가 만드는 정적 HTML(세션 뷰어, 아카이브 첫 페이지, 참고자료 페이지)의
설계 의도 계약서다. 참조 목업이 없으므로 `visual-qa` 스킬이 이 문서를 판정 기준으로 렌더 결과를
반복 검수한다(승인까지 무한 루프, spec §"뷰어 품질 게이트"). 모든 색상·간격·반경·타입 크기는
아래 토큰에서 나오며, 토큰에 없는 값을 코드에 쓰면 먼저 이 문서에 토큰을 추가한다.

## 0. 리서치 로그

이 프로젝트는 참조 목업이 없는 그린필드이며, 마케팅 랜딩 페이지가 아니라 광고 없는
문서/대시보드형 내부 도구다. `frontend` 스킬의 Design System Gate(그린필드 분기)에 따라
아래 리서치 레인을 실행했다 — 줄이 없는 레인은 실행되지 않은 것이다.

- **임베디드 참조**: `_INDEX.md`에서 3개 후보를 추림 — `notion.md`(따뜻한 미니멀, 에디토리얼
  reading 톤), `linear.app.md`(초미니멀·정밀, 칩/필터/탭 밀도가 높은 제품 UI), `mintlify.md`
  (reading-optimized 문서 플랫폼). **Layer A로 `taste-skill.md`, Layer B로 `linear.app.md`를
  전체 정독**했다. `taste-skill.md`는 자체 헤더에 "랜딩 페이지·포트폴리오·리디자인용, 대시보드·
  데이터 테이블·멀티스텝 제품 UI 아님"이라고 명시하므로 히어로/CTA/마케팅 카피 규칙은 이
  제품에 적용하지 않는다 — 타이포 스케일 절제, 색 일관성 잠금(단일 액센트, 장식적 사용 금지),
  코너 반경 일관성 잠금, 버튼 대비 검증, 상태 완전성(hover/active/focus/disabled/empty) 같은
  범용 안티슬롭 규율만 가져왔다. `linear.app.md`는 다크 모드 시스템이지만(이 제품은 라이트
  전용, §1 참고) **구조 문법만 추출**했다: 반투명 대신 tint 배경의 필 칩(포지션/주제/@멘션
  칩), 8px 기반 스페이싱, 보더 기반 elevation(그림자 최소화), 반경 스케일 단계(2/6/8/12/pill).
  실제 색상·다크 팔레트·Inter 특정 OpenType 설정은 가져오지 않았다(이 제품은 라이트 전용, 시스템
  폰트 전용이라 브랜드 폰트 자체가 해당 없음).
- **Lazyweb**: 2개 쿼리, 4개 화면을 실제로 열어봄. `"sports coaching video feedback notes
  timeline"` → apollo(회의 영상, 요약/트랜스크립트/트래커/댓글 탭이 영상 바로 아래, 우측에
  Outcome/Next Steps/Objections/Pain Points로 라벨링된 카드), metaview(좌측 영상 플레이어 +
  Transcript/Video 탭, 우측에 지표 카드와 태그성 pill). `"analytics dashboard filter tag chips
  list"` → front, dub(필터 드롭다운 + 사이드바 내비 + 태그 대시보드). **가져온 레이아웃 문법**:
  영상을 고정하고 그 옆(또는 아래)에 탭으로 전환되는 콘텐츠 목록을 두는 구조, 그리고 노트를
  "문제/누구/대신" 같은 라벨-값 쌍 카드로 쪼개는 문법 — 이것이 §4 카드 해부의 dl 구조와 §5 목차
  탭 구조의 실제 제품 근거다. 스크린샷 자체는 참고용이며 그대로 베끼지 않았다.
- **Imagen 드래프트**: 건너뜀 — 이 환경 툴셋에 이미지 생성 도구가 없음. 이 제품은 원래도
  사진/일러스트 히어로가 없는 텍스트+영상 문서형 UI라 영향이 작다.
- **ui-ux-db**: `content card list filter chips reading app` 도메인 검색 실행 — 날씨/CRM/
  뉴스미디어 3건만 매칭되고 "리딩 앱" 전용 카테고리는 DB에 없음을 확인. 팔레트 판단은 라이트
  전용·카테고리별 포지션 색이라는 이미 정해진 제약(spec, plan §5) 안에서 자체적으로 했다.
- 커밋한 방향(1~2문장): 이 제품은 "코치의 판서를 다시 넘겨보는 조용한 리딩 문서"다 — 장식은
  없고, 영상은 항상 손 닿는 곳에 고정되며, 색은 포지션/주제를 구분하는 데만 쓴다. 시그니처는
  스티키 플레이어와 카드 사이의 스크롤 리듬(scroll-margin-top으로 카드가 플레이어에 가리지
  않는 것)이다.

## 1. 토큰

라이트 테마만 지원한다 — plan의 사용자 답 "Q2 라이트만"과 plan §5의
"v1 라이트만"을 따른다. `prefers-color-scheme: dark` 미디어 쿼리를 만들지 않는다. 액센트는 "피치 그린"
(축구장 잔디 그린) 하나뿐이며 인터랙티브 요소(링크, 포커스, 활성 탭/버튼)에만 쓰고 장식에는
쓰지 않는다(taste-skill 색 일관성 잠금).

### 색상

| 역할 | 토큰 | 값 | 용도 |
|---|---|---|---|
| 배경 | `--bg` | `#FFFFFF` | 페이지 배경 |
| 표면 | `--surface` | `#F6F8F7` | 카드/패널/필터 바 배경 |
| 표면(눌림) | `--surface-sunken` | `#EFF2F0` | details 열림, 비활성 필터 영역 |
| 본문 텍스트 | `--ink` | `#14181C` | 제목, 본문 |
| 보조 텍스트 | `--muted` | `#57606A` | 메타, 캡션, 타임스탬프 (흰 배경 대비 ≥4.5:1) |
| 보더 | `--line` | `#E3E6E8` | 카드/입력/구분선 |

않는다. 이 표에 없는 raw hex는 코드에 쓰지 않는다 — 필요하면 표에 먼저 추가한다.

### 간격 (base 4px)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-1` | 4px | 칩 내부 아이콘-라벨 간격 |
| `--space-2` | 8px | 칩 사이 간격, 인라인 그룹 |
| `--space-3` | 12px | 폼/버튼 내부 패딩 |
| `--space-4` | 16px | 카드 내부 패딩, 섹션 사이 기본 간격 |
| `--space-6` | 24px | 카드 사이 간격, 레이아웃 컬럼 gap |
| `--space-8` | 32px | 섹션(헤더/필터/카드 목록/푸터) 사이 큰 간격 |

간격 의도는 위 토큰만 쓴다. `clamp()`, `auto`, `%`, `minmax()` 같은 브라우저 메커닉스는
토큰화하지 않고 그대로 raw로 쓴다(design-system-architecture 규칙).

### 반경

| 토큰 | 값 | 용도 |
|---|---|---|
| `--radius-sm` | 8px | 카드, 입력, 이미지 |
| `--radius-md` | 12px | 패널, details, 모달성 요소(없으면 미사용) |
| `--radius-full` | 9999px | 칩, pill, 필터 리셋 버튼 |

코너 반경은 이 3단계만 쓴다(모양 일관성 잠금) — 카드/이미지는 항상 `--radius-sm`, 칩은 항상
`--radius-full`, 섞어 쓰지 않는다.

| 레벨 | 크기 | 굵기 | 행간 | 용도 |

## 3. 레이아웃

### 1024px 이상 (2컬럼 그리드)

```
.layout { display: grid; grid-template-columns: minmax(420px, 44%) 1fr; gap: var(--space-6); }
.side   { position: sticky; top: 0; height: 100dvh; overflow: auto;
          display: flex; flex-direction: column; gap: var(--space-4); }
```

- 좌측 `.side`: 플레이어(16:9, `aspect-ratio: 16 / 9`) + 파트 전환 버튼 줄 + 목차 탭(§5). 뷰포트에
  sticky로 붙고 자체 스크롤(`overflow: auto`)을 가지므로 목차가 길어도 플레이어는 화면 안에
  고정된다.
- 우측: 헤더(세션 제목, 날짜), 필터 바(§6), 결과 수("피드백 n/m"), 카드 목록(§4), 푸터.

### 1024px 미만 (단일 컬럼, `display: contents` 기법)

```
@media (max-width: 1023.98px) {
  .side { display: contents; }
}
```

`.side`에 `display: contents`를 주면 `.side` 자신의 박스가 사라지고 그 자식(플레이어 래퍼,
파트 전환, 목차)이 부모(`.layout`, 실제로는 페이지 최상위 flex/grid 컨테이너)의 직속 자식으로
평면화된다. 이렇게 하면 플레이어 래퍼가 `.side`의 좁은 스크롤 컨테이너가 아니라 **페이지 전체
기준으로 상단에 sticky**할 수 있다(`.player-wrapper { position: sticky; top: 0; z-index: 10; }`).
목차는 흐름 속 `<details>`로, 필터 바는 `<details>` "필터 (n)"으로 접힌다(§5, §6).

### 헤더/세션 제목이 플레이어보다 위에 오도록 하는 순서 (plan §12-10)

`display: contents`로 평면화되면 소스 순서상 플레이어가 헤더보다 먼저 오게 되어 플레이어가
페이지 맨 위에 튀어 오를 수 있다. 이를 막기 위해 페이지 최상위 컨테이너를 `display: flex;
flex-direction: column;`으로 두고, 평면화된 모든 형제 요소에 명시적 `order`를 지정한다:

| 요소 | `order` | 비고 |
|---|---|---|
| 헤더(세션 제목/날짜) | 0 | 항상 최상단 |
| 파트 전환 버튼 | 1 | (1024px 미만에서만 플레이어 위/바로 아래로 노출) |
| 플레이어 래퍼 | 2 | `position: sticky; top: 0` |
| 목차 `<details>` | 3 | |
| 필터 바 `<details>` | 4 | |
| 결과 수 | 5 | |
| 카드 목록 | 6 | |
| 푸터 | 7 | |

`order`는 flex/grid 아이템에만 적용되므로, 페이지 최상위 컨테이너가 flex가 아니면 이 규칙은
무효다 — 1024px 미만 미디어 쿼리 안에서 최상위 컨테이너에 `display: flex; flex-direction:
column;`을 함께 지정해야 한다.

### 카드의 `scroll-margin-top` (plan §12-10)

목차 클릭이나 앵커 이동으로 카드로 스크롤할 때 sticky 플레이어에 카드 상단이 가려지면 안 된다.
카드는 sticky 플레이어의 실제 높이 + 여백만큼 `scroll-margin-top`을 갖는다:

```
.card { scroll-margin-top: calc(var(--sticky-player-h) + var(--space-4)); }
```

`--sticky-player-h`는 플레이어 래퍼의 실측 높이(16:9 비율이므로 뷰포트 폭에 따라 달라짐)를
런타임에 `ResizeObserver` 또는 로드 시 1회 측정해 루트 요소에 세팅하는 CSS 커스텀 프로퍼티다.
1024px 이상에서는 플레이어가 `.side` 자체 스크롤 안에 있어 카드 스크롤에 영향을 주지 않으므로
이 계산은 1024px 미만에서만 의미가 있다(1024px 이상에서는 `--sticky-player-h`를 0으로 둬도 무방).

### 깊이/표면

전략: **보더 우선, 그림자는 sticky 플레이어 1곳에만**. 카드/입력/필터 칩은 `1px solid
var(--line)`로만 구분하고 그림자를 쓰지 않는다. sticky 플레이어 래퍼만 아래 콘텐츠와 겹칠 때
구분되도록 `box-shadow: 0 2px 8px rgba(20,24,28,0.08)`를 준다(연한 그림자 1단계, 화면 안
텍스트 대비에는 영향 없음).

## 4. 카드 해부

카드 루트는 `<article class="card" data-video data-start data-pos data-topics
data-member-ids>` (필터링용 data 속성). `a`, `button`, `summary` 태그가 아닌 카드 영역 클릭은
전부 그 카드의 시작 시각으로 `seek`한다(카드 전체가 클릭 타깃 — 44px 미만의 좁은 텍스트만
클릭되게 하지 않는다, §11).

카드 내부 순서:

1. **헤더 줄**: 시간 칩 + 파트 칩 + 브레드크럼.
   - 시간 칩: 카드의 시작 시각 `start`가 3600초 미만이면 `m:ss`(예 `12:34`),
     3600초 이상이면 `h:mm:ss`(예 `1:02:05`)로 표시한다. 영상 전체 길이 `duration`으로
     형식을 결정하지 않는다(plan §13.2 item 5). 테스트명은
     "카드는 m:ss / h:mm:ss 시간 칩을 보인다"이며 1시간 경계 전후를 포함한다.
   - 파트 칩: `P2`처럼 파트 번호 표기, 다중 파트 세션에서만 노출.
   - 브레드크럼: `경기 › 주제` (`aria-hidden` 구분자 `›`).
2. **제목**: `<h3>` 유닛 제목.
3. **시작 이미지**: `<img>`에 실제 추출 프레임의 width/height 속성을 그대로 쓴다(레이아웃
   시프트 방지, CLS 없음). 클릭 시 해당 시각으로 seek(카드 공통 클릭 규칙과 동일 동작이므로
   이미지 자체에 별도 핸들러가 필요 없다 — `a`가 아니므로 카드 클릭에 포함됨).
4. **칩 행**: 유닛의 원래 `position_tags`를 포지션 칩으로 표시한다(루트 그룹
   GK/DF/MF/FW에 해당하는 `--pos-*` 색 사용). `posClosure(unit)`는 필터용 `data-pos`에만
   사용하며 조상/자손 칩을 추가로 표시하지 않는다. 주제 칩은 중립 색
   (`--surface-sunken` 배경 + `--ink` 텍스트), `@멘션` 칩은 직접 언급된 팀원을
   `@닉네임` 형태로 표시한다.
5. **관련 팀원**: `relatedMembers(unit)` 결과를 명단 순서로 나열(포지션 관련 ∪ 직접 언급).
6. **노트 `<dl>`**: `문제 → 누구 → 대신 → 상세` 순서 고정(상세는 옵셔널이면 dt/dd 자체를
   생략, 순서는 항상 이 순서). 값은 plain text를 escape 후 `\n`을 `<br>`로 렌더.
7. **중요 이미지**: 있을 때만 섹션 자체를 렌더(§9 빈 상태). PC(1024px 이상) 2열 그리드, 모바일
   1열, 각 이미지 아래 캡션(Caption 스타일). 콘텐츠 스트레스: 최대 4장(contracts 상한)까지
   와이드 이미지·긴 캡션에서도 레이아웃이 깨지지 않아야 한다.
8. **유사한 과거 피드백**: 있을 때만, 세션 날짜 + 링크(해당 세션의 유닛 앵커로 이동).
9. **참고자료**: 제목, 언어 배지(`lang` 코드, 예 `EN`/`JA`), 그리고 링크:
   - `lang !== "ko"`: "요약" 링크(→ 아카이브의 `refs/<id>.html`, 한국어 요약 페이지) + "원문 ↗"
     링크(외부 원문 URL, `target="_blank" rel="noopener"`).
   - `lang === "ko"`: "원문 ↗" 링크만(이미 한국어이므로 별도 요약 페이지를 만들지 않는다 —
     "요약" 링크 자체가 렌더되지 않는다).
10. **"유튜브에서 보기 ↗"**: `https://youtu.be/<videoId>?t=<startSeconds>` 형태의 새 탭 링크.
    항상 렌더(플레이어 임베드 가능 여부와 무관 — JS 없이도 동작해야 한다는 plan §1 요구사항).

## 5. 목차 탭

`<div role="tablist">` 안에 탭 2개, `<button role="tab" aria-selected="true|false"
aria-controls="...">`로 구현한다:

- **경기별**: 경기 → 주제 → 피드백 3단 트리. 각 주제 노드는 `topics[].summary` 텍스트를 함께
  보인다(Lazyweb apollo 참조에서 가져온 "탭 아래 요약 카드" 문법).
- **주제별**: 경기 무관, 주제 태그 → 피드백 목록. 각 태그 옆에 그 태그가 달린 피드백 개수를
  괄호로 표시(`빌드업 (5)`).

TOC 항목 클릭은 **seek하지 않는다** — 대상 카드로 스크롤(`scrollIntoView`, `scroll-margin-top`
적용됨) 후 카드에 강조 클래스(예 `.card--highlighted`, `--accent` 보더 2px, 600ms 후 제거)를
잠깐 준다. 필터로 숨겨진 카드에 해당하는 TOC 항목은 같이 숨긴다(§6).

## 6. 필터 바

필터 그룹은 4개, 그룹 간 **AND**, 그룹 내부는 그룹마다 다르다:

| 그룹 | 선택 방식 | 그룹 내부 결합 |
|---|---|---|
| 포지션 트리 | 단일 선택(칩 1개만 활성) | — |
| 주제 | 다중 선택 | **OR** |
| 언급 선수 | 단일 선택 | — |
| 팀원 관련 | 단일 선택 | — |

포지션 트리는 중첩 칩으로 표현한다: `GK | DF(CB, FB(LB RB LWB RWB)) | MF(CDM CM CAM LM RM) |
FW(ST CF LW RW LF RF)`. 모든 노드는 단일 선택 가능한 태그다.
포지션 필터는 선택한 포지션이 `posClosure(unit)`에 포함된 카드를 보인다.
`posClosure(unit) = ∪(anc(t) ∪ desc(t))`이며 `t`는 유닛의 원래 `position_tags`다.
`anc`는 자기 자신과 조상, `desc`는 자기 자신과 자손을 포함한다(plan §4-C).
따라서 FB 선택은 LB 태그 피드백을 포함하고, LB 선택도 FB·DF 태그 피드백을 포함한다.
CB와 LB처럼 공통 조상만 가진 다른 가지는 서로 매칭하지 않는다.
폐포는 빌드 타임에 계산해 `data-pos`에 넣으며, 뷰어에는 트리 로직을 두지 않는다.

"언급 선수" 필터는 선택한 id가 `member_ids`에 있는 카드만 보인다.
"팀원 관련" 필터는 선택한 id가 `relatedMembers(unit)` 결과에 있는 카드를 보인다.
`relatedMembers(unit)`는 직접 언급된 팀원 또는 유닛의 원래 포지션 태그와 팀원의
포지션 중 하나가 동일하거나 조상/자손 관계인 팀원을 중복 없이 명단 순서로 반환한다.
팀원의 주 포지션만 검사하지 않으며, 모든 `positions`를 검사한다.
카드의 "관련 팀원" 목록도 이 결과와 같아야 한다.

- **리셋 버튼**: 모든 필터를 초기 상태로. `--radius-full` pill 버튼.
- **결과 수**: "피드백 n/m" 형태(n = 현재 표시, m = 전체).
- **모바일(1024px 미만)**: 필터 바 전체가 `<details><summary>필터 (n)</summary>...</details>`로
  접힌다. `n`은 현재 활성 필터 개수(그룹당 0 또는 1 이상 선택 시 +1, OR 그룹은 선택된 태그
  개수와 무관하게 그룹당 1로 카운트).

필터 결과 0건이면 카드 목록과 목차 항목이 모두 사라지고 빈 상태(§9)를 보인다.

## 7. 영상 전환

- 파트 전환 버튼: `<button aria-pressed="true|false">Part 2</button>`, 활성 파트만
  `aria-pressed="true"`.
- 카드 클릭 시:
  - **같은 파트**(현재 재생 중인 videoId와 카드의 videoId가 같음): `player.seekTo(t, true);
    player.playVideo();`
  - **다른 파트**: `player.loadVideoById({ videoId, startSeconds: t });` (전환 + seek을 한 번에).
- **onReady 이전 큐**: 플레이어가 아직 `onReady` 콜백을 받지 못한 상태에서 카드가 클릭되면
  seek/load 요청을 큐에 저장하고, `onReady`에서 큐를 순서대로 flush한다.
- **스크립트 로드 순서** (plan §12-8): `VIEWER_JS`를 `iframe_api` 스크립트보다 **먼저** 로드한다.
  `VIEWER_JS` 초기화 로직은 `window.YT && YT.loaded`이면 즉시 플레이어를 생성하고, 아니면
  `window.onYouTubeIframeAPIReady`에 생성 콜백을 등록한다. (API 스크립트가 나중에 로드되며
  `onYouTubeIframeAPIReady`를 호출하는 경쟁 상태를 양쪽 다 커버한다.)
- **테스트 훅**: `document.body.dataset.video`(현재 재생 중인 videoId)와
  `window.fcPlayer`(YT.Player 인스턴스, `getCurrentTime()`/`getVideoData()` 등 조회용)를
  항상 최신 상태로 유지한다.
- **임베드 불가 플레이스홀더**: 임베드 가능 여부는 현재 선택하거나 카드 클릭으로 전환하려는
  영상별로 판정한다. 해당 영상이 `embeddable: false`이면 iframe 대신
  플레이스홀더(썸네일 또는 텍스트 카드 + "유튜브에서 시청 ↗" 새 탭 링크)를 보인다.
  일부 파트만 임베드 불가인 세션에도 같은 규칙을 적용한다. 카드에서 전환한 경우
  새 탭 링크는 해당 영상의 카드 시작 시각을 가리킨다. 임베드 가능한 파트로 돌아오면
  플레이어를 다시 제공한다. 각 카드의 "유튜브에서 보기 ↗" 링크(§4)는 항상 유지한다.

## 8. 한글 타이포

폰트 스택은 시스템 폰트만 사용한다(웹폰트 로드 없음, plan §5):

```
font-family: -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif;
```

줄바꿈/개행 규칙(모든 텍스트 블록에 적용):

| 속성 | 값 | 목적 |
|---|---|---|
| `word-break` | `keep-all` | 한글 어절 단위 줄바꿈(음절 단위로 끊기지 않음) |
| `overflow-wrap` | `anywhere` | 긴 영문 URL/닉네임이 있어도 가로 스크롤 없이 줄바꿈 |
| `line-break` | `strict` | 구두점·문장부호가 줄 시작에 오지 않도록(엄격 규칙) |
| `text-wrap` | 제목: `balance`, 본문: `pretty` | 제목은 균형 잡힌 줄 길이, 본문은 마지막 줄 orphan 방지 |

최소 크기와 행간은 §1 타입 스케일 표를 따른다(읽기 단락 14px 이상, 행간 1.6–1.7). 이 규칙들은
`visual-qa`의 CJK 검사(조사/어미 고아 줄, 짧은 주어-술어 분리, 연결어 중간 분리, 인용/출처
영문 문자열 줄바꿈, 제목 한 글자 고아 줄 등)를 통과하기 위한 최소 조건이며, `similarityScore`가
높아도 이 클래스의 줄바꿈이 하나라도 나오면 차단 결함이다(§13).

## 9. 빈 상태

| 상황 | 표시 |
|---|---|
| 필터 결과 0건 | "조건에 맞는 피드백이 없어요" 텍스트 + 리셋 버튼. 카드 목록·목차 항목 모두 숨김. |
| 빈 아카이브(발행된 세션 없음) | 아카이브 첫 페이지에 "아직 발행된 세션이 없어요." 텍스트만, 세션 카드 그리드 없음. |
| 중요 이미지 없는 유닛 | "중요 이미지" 섹션 헤더/그리드 자체를 렌더하지 않는다(빈 그리드나 플레이스홀더 박스를 보이지 않는다). |
| disabled 모드 | `manifest.roster_path`가 있으면 해당 명단으로 언급·팀원 관련 필터와 카드 정보를 정상 제공한다. 명단 경로가 없으면 `member_ids`는 빈 배열만 허용하며, "언급 선수"·"팀원 관련" 필터를 화면과 키보드 조작에서 숨기고 `@멘션` 칩·"관련 팀원" 섹션을 렌더하지 않는다. 필터 DOM 노드의 존재 여부 자체는 판정 조건이 아니다. disabled 모드에서는 명단 유무와 관계없이 유사 과거 피드백 섹션을 생략한다. |

disabled 모드의 taxonomy는 첫 사용 시 번들의 `scripts/taxonomy.default.yaml`을
`$OMT_DIR/fc-feedback/<sid>/taxonomy.yaml`로 복사한 사본을 사용한다. 이후 check와
taxonomy add도 이 사본만 사용하며 번들 원본은 변경하지 않는다(plan §13.1 item 2).
명단이 없으면 alias 정규화를 생략한다. similar는 빈 결과로 건너뛰고,
`render --site-only`로 로컬 사이트만 만들며 아카이브의 `index.json`은 갱신하지 않는다
(plan §12 item 2, §13.2 item 3).

## 10. 아카이브 첫 페이지 / 참고자료 페이지

아카이브 첫 페이지와 참고자료 페이지는 JS 없이 완전히 동작해야 한다
(정적 HTML, 뷰어 스크립트 2개는 세션 페이지 전용).
세션 뷰어·아카이브 첫 페이지·참고자료 페이지 모두
`<meta name="robots" content="noindex, nofollow">`를 포함한다.
프로젝트 Pages 하위의 `robots.txt`로 이 요건을 대체하지 않는다(plan §5, §12 item 14).

### 아카이브 첫 페이지

- 세션 카드를 최신순(날짜 desc)으로 나열: 날짜, 제목, 파트 수, 피드백 개수, 주제 칩 목록.
- 카드 목록 아래(또는 옆) "주제별 전체 피드백" 링크 — 아카이브 전체를 가로지르는 주제별 뷰로
  이동.
- 빈 상태는 §9 참고.
- `<meta name="robots" content="noindex, nofollow">` 포함(공개 저장소지만 검색 노출 방지).
- 푸터 고지 문구: "팀 내부 피드백용 비공식 정리 문서입니다. 영상 저작권은 원 게시자에게
  있습니다." — 세션 페이지 푸터와 동일 문구를 아카이브 첫 페이지에도 둔다.

### 참고자료(refs) 페이지

- 제목, `kind`(`eafc`/`tactics`) 배지 + 언어 배지.
- 원문 링크("원문 ↗", 새 탭).
- 한국어 요약(`summary_ko`).
- 핵심 포인트 목록(`key_points_ko`).
- 원문 | 한국어 2열 표(`translations[]`, 각 행 원문 발췌 + 한국어 번역, 최대 5행).
- "아카이브로 돌아가기" 링크.
- `ko` 언어 참고자료는 이 페이지 자체가 생성되지 않는다(§4 참고자료 규칙과 동일 이유).

## 11. 접근성

- **포커스**: 모든 인터랙티브 요소(칩, 버튼, 탭, 링크, details/summary)는 키보드 포커스 시
  `outline: 2px solid var(--focus); outline-offset: 2px;`를 보인다. `outline: none`으로 지우고
  대체 인디케이터 없이 두지 않는다.
- **대비**: 본문/보조 텍스트는 배경 대비 4.5:1 이상(§1에서 `--ink`, `--muted`, `--accent` 모두
  흰 배경 기준 확인됨), 포지션 칩 텍스트도 그 칩 배경 대비 4.5:1 이상을 목표로 한다. 인터랙티브
  요소의 비텍스트 대비(칩 보더, 아이콘)는 3:1 이상.
- **탭 타깃**: 버튼, 탭, 칩, 파트 전환 버튼, details summary의 클릭 가능 영역은 최소 44×44px
  (padding으로 확보, 시각적 크기가 작아도 히트 영역은 44px 이상).
- 목차 탭은 `role="tablist"`/`role="tab"`/`aria-selected` ARIA 패턴을 정확히 따른다(§5). 파트
  전환 버튼은 `aria-pressed`(§7). 이 둘은 스크린리더 사용자에게도 현재 선택 상태를 전달하는
  유일한 수단이므로 시각적 스타일만으로 대체하지 않는다.

## 12. 캡처 세트 (visual-QA)

기본 캡처 세트는 1024×768 기본 상태를 포함한 **33장 고정**이다(plan §12-3).
첫 회차와 승인(APPROVE) 회차에는 33장 전체를 새로 촬영한다. 중간 회차에는 수정의 영향을
받은 페이지/상태만 재촬영할 수 있지만, 전체 판정 대상의 열거는 항상 아래 33개다.
`capture-manifest.json`은 33개 전체를 기록하며, 부분 재촬영 시 영향받지 않은 유효한 증거를
유지하고 재촬영한 항목의 파일·해시·mtime을 갱신한다. 오래된 증거의 재사용은 허용하지
않으며 신선도 조건은 §13 item 8을 따른다(visual-qa SKILL.md:42, 240).
뷰어 상태 캡처는 파트가 2개인 현재 세션 fixture를 사용한다.

### 기능 검사 (`functional.json`)

각 항목은 `{"name", "kind": "dom" | "player_api", "pass": bool, "skipped_reason": string |
null}` 형태로 기록한다(plan §13.1-1). `kind: "dom"` 항목은 헤드리스에서도 항상 판정 가능하므로
`skipped_reason`을 허용하지 않는다 — 전부 `pass: true`여야 한다. `kind: "player_api"` 항목은
헤드리스 재생 제약으로 스킵을 허용하되(`skipped_reason`에 사유), **승인 회차의 headed 재시도**
(`capture.sh --headed`)에서는 스킵을 허용하지 않고 전부 `pass: true`여야 한다(plan §14.8).

- `dom`: 카드 클릭 후 `document.body.dataset.video`가 해당 카드의 videoId와 일치,
  다른 파트 카드 클릭 후 해당 파트 버튼만 `aria-pressed="true"`,
  카드 클릭 후 스크롤/강조 상태 확인(plan §12 item 6),
  목차 클릭 후 대상 카드로 스크롤·강조되며 seek는 발생하지 않음(§5),
  필터 리셋 후 결과 수가 전체 m으로 복귀, 탭 `aria-selected` 전환.
  `dataset.video` 일치는 영상 선택의 증거이며 seek 시각 정확도의 증거로 사용하지 않는다.
- `player_api`: `window.fcPlayer.getCurrentTime()`이 클릭한 카드의 시작 시각과 ±2초 이내로
  일치, `window.fcPlayer.getVideoData().video_id`가 전환 후 목표 파트의 videoId와 일치.

## 13. 판정 기준

`visual-qa`의 이중 오라클(Pass A/B) 각각이 `VERDICT: PASS`이고 두 패스 모두 `BLOCKING`이
비어 있어야 승인(APPROVE)이다. 아래는 이 제품에서 **차단(blocking) 결함**으로 취급하는 항목 —
`similarityScore`나 전반적 인상이 좋아도 아래 중 하나라도 있으면 REVISE/FAIL이다:

1. **CJK 줄바꿈 위반** (§8): 조사/어미 고아 줄, 주어-술어 분리, 연결어 중간 분리, 인용/출처
   영문 문자열 줄바꿈, 제목 한 글자/음절 고아 줄, 글리프 깨짐(tofu) — 페이지 전수 검사, 표본
   추출 금지(visual-qa SKILL.md:207-213).
2. **토큰 이탈**: §1에 없는 raw hex, 임의 px 간격/반경, §1 타입 스케일에 없는 폰트 크기.
3. **레이아웃 계약 위반**: 1024px 이상에서 `.side`가 sticky하지 않음, 1024px 미만에서 헤더/
   세션 제목이 플레이어보다 아래에 옴(order 누락), 카드가 sticky 플레이어에 가려짐
   (`scroll-margin-top` 누락/오계산).
4. **카드 필드 누락/순서 오류**: 노트 dl이 문제→누구→대신→상세 순서가 아님, 시간 칩이 §4의
   m:ss/h:mm:ss 분기를 따르지 않음, ko 참고자료에 "요약" 링크가 잘못 노출됨(또는 비-ko
   참고자료에 "요약" 링크가 없음), 시작 이미지에 width/height 속성이 없어 레이아웃 시프트 발생.
5. **필터/목차 계약 위반**: 그룹 간 AND가 OR처럼 동작, 주제 그룹 내부가 OR가 아님, 목차 클릭이
   seek를 발생시킴(seek 없이 스크롤+강조만 해야 함), 필터 0건인데 목차 항목이 남아있음.
6. **영상 전환 계약 위반**: 같은 파트에서 `loadVideoById`를 호출(불필요한 재로드), 다른 파트에서
   `seekTo`만 호출(전환 없이 시각만 이동), `onReady` 이전 클릭이 무시됨(큐잉 없음), API 스크립트가
   `VIEWER_JS`보다 먼저 로드되어 있음.
7. **기능 검사 실패**: §12의 필수 검사 항목이 누락됨, `kind: "dom"` 항목 중
   `pass`가 true가 아니거나 `skipped_reason`이 null이 아닌 항목이 있음.
   일반 헤드리스 회차의 `player_api` 실패는 재생 제약에 대한 `skipped_reason`이 있을 때만
   스킵으로 기록할 수 있다. headed 실행은 스킵 없이 pass/fail로 기록해야 하며,
   승인 회차에는 T10의 2파트 fixture로 `capture.sh --headed`를 실행한
   `player_api` 항목 전부가 `pass: true`, `skipped_reason: null`이어야 한다(§12).
8. **캡처 세트 불완전/신선도 위반**: `capture-manifest.json` 길이가 33이 아니거나,
   §12에 열거한 페이지·상태·뷰포트 조합이 누락·중복됨, PNG가 아닌 파일이 섞여 있음,
   또는 검증 대상 소스보다 오래된 캡처를 사용함. 중간 회차의 부분 재촬영은 허용하지만
   전체 열거를 32개로 줄이지 않는다. 첫 회차와 승인 회차에는 33장 전체를 새로 촬영한다.
   신선도 검사는 `find render.ts DESIGN.md __fixtures__/qa -newer <가장 오래된 캡처>`를
   실행해 출력이 없어야 한다(plan §12-12). 공통 소스 변경으로 기존 증거가 이 조건을
   충족하지 못하면 해당 증거도 다시 촬영한다.
9. **접근성 회귀**: 포커스 링이 안 보임, 탭 타깃이 44px 미만, `role="tablist"`/
   `aria-selected`/`aria-pressed` 중 하나라도 빠짐.

차단이 아닌 항목(다음 라운드로 넘겨도 되는 것): 서브픽셀 렌더링 차이, 폰트 힌팅에 따른 안티
앨리어싱 차이, 브라우저별 스크롤바 폭 차이로 인한 1–2px 디프 — 이런 것들은 `similarityScore`
저하의 원인이 될 수 있지만 그 자체로는 차단 결함이 아니다.
