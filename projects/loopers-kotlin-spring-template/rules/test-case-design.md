# 테스트 케이스 설계 판단 규칙

스펙에서 테스트 케이스를 어떻게 뽑고 테스트 데이터를 어떻게 구성할지를 다루는 규칙이다. 문서를 열어 판단 기준을 확인한다.

- `docs/testing/test-case-extraction.md` — **테스트 케이스 추출(스펙에서 무엇을 테스트할지)**: 역할, 책임 단위로 스펙 기준 분해하기, 위험 신호, 스펙-코드 간극(TDD), 추출 절차(스펙 레퍼런스 읽기·테스트 레벨 결정·레벨별 케이스 추출·테스트 스켈레톤 작성), 스펙 변경 다루기, 테스트 생성을 건너뛰는 경우(순수 데이터 객체·비즈니스 로직 없는 인프라 트리거)
- `docs/testing/test-data-design.md` — **테스트 데이터 설계(BVA·ECP·Decision Table)**: BVA 경계값 분석, ECP 동등분할, BVA+ECP 결합(구간 기반 분할), Decision Table 다중 조건 조합, 조합 폭발 대응 절차

**관련 규칙**: 테스트 구조·네이밍은 `test-authoring.md` rule에, 레벨별 검증 대상·안티패턴은 `test-strategy.md` rule에 있다.
